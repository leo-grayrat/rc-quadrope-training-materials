# 工作空间、功能包与第一个 C++ 节点

这一篇解决一个完整问题：一份 C++ 程序怎样进入 ROS2 的构建和运行体系，并被 ROS2 发现。

第三次已经学过 C++、多文件工程和 CMake，这里只加入 ROS2 所需的组织和运行关系。

## 1. 先分清目录、程序和运行时对象

| 层次 | 是什么 | 这次的例子 |
|---|---|---|
| 工作空间 workspace | 一组 ROS2 包共同开发、编译的目录 | `~/ros2_ws` |
| 功能包 package | 源码、依赖、构建规则、launch 等的组织单位 | `robot_controller` |
| 可执行程序 executable | 编译后可以被 `ros2 run` 启动的程序 | `hello_node` |
| 节点 node | 程序运行后创建的 ROS2 运行时对象 | `/hello_node` |

一个包可以生成多个可执行程序，一个程序也可以创建多个节点。下面的例子中，每个可执行程序创建一个主要节点。

先建立工作空间和 C++ 包：

```bash
source /opt/ros/humble/setup.bash

mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src

ros2 pkg create \
  --build-type ament_cmake \
  robot_controller \
  --dependencies rclcpp std_msgs sensor_msgs
```

这里第一次出现两个 ROS2 自己的名字：

- `ament_cmake`：ROS2 C++ 包使用的一种构建类型，生成的包继续用 CMake 描述怎样编译和安装；
- `rclcpp`：ROS2 的 C++ 客户端库，后面的节点、定时器、发布者和订阅者都从这里创建。

`std_msgs`、`sensor_msgs` 是后面消息通信会用到的消息包。

主要文件是：

```text
robot_controller/
├── CMakeLists.txt
├── package.xml
├── include/robot_controller/
└── src/
```

`package.xml` 记录包和依赖，`CMakeLists.txt` 描述怎样把源码构建并安装成 ROS2 能启动的程序。

## 2. 从 C++ 源码到 `ros2 run`

在 `robot_controller/src/hello_node.cpp` 中写：

```cpp
#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class HelloNode : public rclcpp::Node
{
public:
  HelloNode() : Node("hello_node")
  {
    timer_ = this->create_wall_timer(1s, [this]() {
      RCLCPP_INFO(this->get_logger(), "hello ros2");
    });
  }

private:
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<HelloNode>());
  rclcpp::shutdown();
  return 0;
}
```

先抓住四条关系：

```text
rclcpp::init
    ↓ 初始化 ROS2 客户端库，并接收 main 的命令行参数
HelloNode
    ↓ 创建节点对象
create_wall_timer
    ↓ 定时产生事件
rclcpp::spin
    ↓ 持续处理定时器、订阅回调等事件
```

节点中的定时器、订阅者等对象产生事件以后，需要执行器调度对应回调；这里 `rclcpp::spin(...)` 使用默认执行器持续处理这些工作。`main(int argc, char * argv[])` 中的 `argc / argv` 是程序收到的命令行参数，继续传给 `rclcpp::init(argc, argv)` 后，ROS2 可以读取自己的命令行选项。

`RCLCPP_INFO(this->get_logger(), ...)` 通过当前节点的 logger 输出一条 INFO 级日志，所以终端输出中会看到 `[INFO]` 和节点名。

这段代码还第一次出现了两种 C++ 写法：

- `[this]() { ... }` 是一个 lambda 回调。定时器到期时执行花括号里的代码，`[this]` 让回调能够访问当前 `HelloNode` 对象；
- `SharedPtr` 是 shared pointer（共享指针）类型。`create_wall_timer()` 返回的定时器保存在成员变量 `timer_` 中；`std::make_shared<HelloNode>()` 创建节点对象并把它交给 `rclcpp::spin()`。

在 `CMakeLists.txt` 的 `ament_package()` 之前加入：

```cmake
add_executable(hello_node src/hello_node.cpp)
ament_target_dependencies(hello_node rclcpp)

install(TARGETS
  hello_node
  DESTINATION lib/${PROJECT_NAME})
```

这段 CMake 把关系接起来：

```text
src/hello_node.cpp
      ↓ add_executable
hello_node
      ↓ ament_target_dependencies
使用 rclcpp
      ↓ install
进入 ROS2 包的安装目录
```

`ament_target_dependencies(...)` 把 ROS2 包依赖接到这个 CMake target 上；生成包中已有的 `ament_package()` 用来把当前工程声明为一个 ament/ROS2 包。

回到工作空间构建并运行：

```bash
cd ~/ros2_ws
colcon build --symlink-install --packages-select robot_controller
source install/setup.bash
ros2 run robot_controller hello_node
```

`colcon` 是这里用来构建 ROS2 工作空间的工具。`--packages-select robot_controller` 只构建这个包；`--symlink-install` 对可符号链接的安装文件使用链接代替复制，开发时修改这类源码或资源后不必反复复制到 `install/`。

终端应每秒出现一次：

```text
[INFO] [...] [hello_node]: hello ros2
```

构建后工作空间会出现 `build/`、`install/`、`log/`；源码仍然放在 `src/` 下。新的终端需要重新 source ROS2 和当前工作空间的 `install/setup.bash`。

## 3. 从运行结果检查程序模型

保持 `hello_node` 运行，另开终端：

```bash
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash

ros2 node list
ros2 node info /hello_node
```

`ros2 node list` 应看到：

```text
/hello_node
```

这时可以把本篇四层关系重新对上：

```text
~/ros2_ws                 workspace
└── src/robot_controller  package

ros2 run robot_controller hello_node
                           executable
             ↓ 运行后创建
/hello_node                node
```

### 检查点

**产物**：一个能够被 `ros2 run` 启动的 `hello_node`。

**给定边界**：包名、可执行程序名、节点名沿用本篇；本题不要求自己设计程序结构。

**判定方式**：

```text
colcon build 成功
        ↓
ros2 run 能启动
        ↓
ros2 node list 出现 /hello_node
        ↓
终端持续打印 hello ros2
```

如果编译成功但 `ros2 run` 找不到程序，先检查 `install(TARGETS ...)` 和当前终端是否重新 `source install/setup.bash`。
