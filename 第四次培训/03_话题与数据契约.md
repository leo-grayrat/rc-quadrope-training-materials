# 用话题连接状态和控制量

上一节已经能运行一个节点。这一篇把控制器真正接到两条数据流上：收到关节状态，算出关节力矩，再发布出去。

先用一个关节跑通，再扩到 12 个关节。

## 1. 定义接口并写出单关节控制器

控制器使用：

```text
/joint_states
执行端 ─────────────→ 控制器

/joint_torques
执行端 ←───────────── 控制器
```

状态消息使用：

```text
sensor_msgs/msg/JointState
```

本次使用三个字段：

```text
name[]      关节名
position[]  位置，rad
velocity[]  速度，rad/s
```

力矩消息使用：

```text
std_msgs/msg/Float64MultiArray
```

其中 `data[]` 保存关节侧力矩，单位 N·m。单关节练习只有 `data[0]`；扩到 12 个关节后，输出顺序固定为第三次程序的 `joint_order`。

在下面的回调参数里会看到：

```cpp
sensor_msgs::msg::JointState::SharedPtr msg
```

上一篇已经见过 `SharedPtr`。这里它表示“收到的 `JointState` 消息对象由共享指针持有”；因此成员字段通过 `msg->position`、`msg->velocity` 这样的 `->` 语法访问。`[this](...){ ... }` 仍然是上一节的 lambda 回调形式，这次多了一个 `msg` 参数，用来接收刚到达的消息。

新建 `robot_controller/src/controller_node.cpp`：

```cpp
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/joint_state.hpp"
#include "std_msgs/msg/float64_multi_array.hpp"

class ControllerNode : public rclcpp::Node
{
public:
  ControllerNode() : Node("controller_node")
  {
    torque_pub_ = this->create_publisher<std_msgs::msg::Float64MultiArray>(
      "/joint_torques", 1);

    state_sub_ = this->create_subscription<sensor_msgs::msg::JointState>(
      "/joint_states", 1,
      [this](const sensor_msgs::msg::JointState::SharedPtr msg) {
        state_callback(msg);
      });
  }

private:
  void state_callback(const sensor_msgs::msg::JointState::SharedPtr msg)
  {
    if (msg->position.empty() || msg->velocity.empty()) {
      return;
    }

    const double q = msg->position[0];
    const double dq = msg->velocity[0];

    const double q_des = 0.0;
    const double dq_des = 0.0;
    const double kp = 20.0;
    const double kd = 1.0;

    const double tau = kp * (q_des - q) + kd * (dq_des - dq);

    std_msgs::msg::Float64MultiArray out;
    out.data = {tau};
    torque_pub_->publish(out);
  }

  rclcpp::Publisher<std_msgs::msg::Float64MultiArray>::SharedPtr torque_pub_;
  rclcpp::Subscription<sensor_msgs::msg::JointState>::SharedPtr state_sub_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<ControllerNode>());
  rclcpp::shutdown();
  return 0;
}
```

本篇采用状态驱动更新：每收到一条 `/joint_states`，控制器计算一次并发布一条 `/joint_torques`。 `create_publisher(..., 1)` 和 `create_subscription(..., 1, ...)` 最后的 `1` 是这里使用的消息队列历史深度：最多保留 1 条尚待处理的消息。控制器只使用最新状态，因此本篇把深度设为 `1`。

类成员中的 `Publisher<...>::SharedPtr` 和 `Subscription<...>::SharedPtr` 分别保存发布者和订阅者对象，使它们在节点运行期间一直存在。

在 `CMakeLists.txt` 中加入：

```cmake
add_executable(controller_node src/controller_node.cpp)
ament_target_dependencies(
  controller_node
  rclcpp
  sensor_msgs
  std_msgs)

install(TARGETS
  hello_node
  controller_node
  DESTINATION lib/${PROJECT_NAME})
```

重新构建并启动：

```bash
cd ~/ros2_ws
colcon build --symlink-install --packages-select robot_controller
source install/setup.bash
ros2 run robot_controller controller_node
```

## 2. 用命令行跑通第一条状态→力矩链

先观察输出：

```bash
ros2 topic echo /joint_torques
```

再从另一个终端发送一次状态：

```bash
ros2 topic pub --once \
  /joint_states \
  sensor_msgs/msg/JointState \
  "{name: ['joint1'], position: [0.5], velocity: [0.1]}"
```

按当前参数：

```math
\tau
=20(0-0.5)+1(0-0.1)
=-10.1\ \mathrm{N\cdot m}.
```

因此 `/joint_torques` 应出现：

```text
data:
- -10.1
```

继续查看 ROS2 图：

```bash
ros2 node list
ros2 node info /controller_node
ros2 topic list -t
ros2 topic info /joint_states
ros2 topic info /joint_torques
```

可以从这些命令确认节点是否存在、话题类型是否正确，以及对应话题当前有几个发布者和订阅者。

## 3. 扩到 12 个关节

**产物**：`controller_node` 从一条 `JointState` 中取得第三次程序需要的 12 个 `q/dq`，并发布 12 个关节力矩。

**给定边界**：

- 输入包含 12 个唯一的目标关节；
- `name`、`position`、`velocity` 都有 12 个元素，且 `name[i]`、`position[i]`、`velocity[i]` 描述同一个关节；
- 输入数组的排列顺序不保证等于 `joint_order`；
- 输出顺序固定为第三次程序已有的 `joint_order`；
- 控制算法沿用第三次已经完成的逻辑。

输入按上述条件给定，完成 `name → index → joint_order` 的映射。

先不用 MuJoCo，通过 `ros2 topic pub` 手工发一条 12 关节状态，再观察：

```bash
ros2 topic echo /joint_torques
```

检查：

1. 输出恰好有 12 个元素；
2. 顺序与 `joint_order` 一致；
3. 选一个输入简单的关节，手算结果与输出一致。

这一条链通过以后，下一篇再把真正的 MuJoCo 执行端接到 `/joint_states` 和 `/joint_torques` 上。
