# 减速器、编码器与关节坐标

上一节的 MuJoCo 控制器直接使用关节角 `q`、关节角速度 `dq` 和关节力矩 `tau`。真实关节电机多了一层机械传动：腿接在减速器输出端，SDK 直接读写的却是电机转子侧。

这会立刻产生一个具体问题：

> 如果机器人关节希望转到 30°，电机 SDK 的位置命令也应该填 30° 吗？

答案取决于减速比。

## 关节转 30°，转子要转多少

把减速比记为 `N`。本培训资料中的关节电机约为 6.33:1，原 `motor.pdf` 也写成 19:3；两者表示同一个比例。

`N=6.33` 的含义是：

```text
转子转 6.33 圈
→ 输出端约转 1 圈
```

因此如果输出端，也就是机器人关节，希望转：

```text
q = 30°
```

转子必须到：

```text
p = 30° × 6.33 = 189.9°
```

这就是为什么真实电机里必须同时区分两套位置：

```text
关节 / 输出端：q
转子侧：       p
```

它们满足：

```math
p=Nq.
```

![](images/video2_01m05s_motor_structure.png)
*视频中的关节电机结构：内侧转子通过减速器带动外侧输出端*

如果上层给出关节目标 `q_des`，发送给转子侧位置接口前要变成：

```math
p_{des}=Nq_{des}.
```

这里连接的是两个不同机械部位的位置；`N` 描述的是减速器两侧的机械传动比例。

## 速度也经过同一个减速比

在相同时间内，转子走过的角度是输出端的 `N` 倍，所以角速度也满足：

```math
\omega=N\dot q.
```

例如关节希望以：

```text
dq_des = 1 rad/s
```

运动，而 `N=6.33`，转子侧目标速度就是：

```text
omega_des = 6.33 rad/s
```

于是位置和速度的命令关系已经有两条：

```text
q_des   → ×N → p_des
dq_des  → ×N → omega_des
```

## 为什么力矩方向正好相反：关节力矩更大

减速器让输出端转得更慢，同时把力矩放大。

忽略传动损耗时，两侧机械功率近似相同：

```math
\tau_m\omega=\tau_j\dot q.
```

这里：

- `tau_m`：转子侧力矩；
- `tau_j`：关节 / 输出端力矩。

刚才已经有：

```math
\omega=N\dot q.
```

代入后：

```math
\tau_m N\dot q = \tau_j\dot q,
```

得到：

```math
\tau_j=N\tau_m.
```

所以如果上层希望关节得到 `tau_j`，转子侧只需要：

```math
\tau_m=\frac{\tau_j}{N}.
```

现在三个最基本的机械换算来自同一个减速器：

| 关节侧目标 | 转子侧命令 |
|---|---|
| `q_des` | `p_des = N q_des` |
| `dq_des` | `omega_des = N dq_des` |
| `tau_j` | `tau_m = tau_j / N` |

## 为什么 PD 增益不能原样塞进转子侧 SDK

上一节的关节侧位置项是：

```math
\tau_j=K_{p,j}(q_{des}-q).
```

现在假设电机驱动器内部直接根据**转子位置误差**工作：

```math
\tau_m=K_{p,m}(p_{des}-p).
```

如果把关节侧的 `Kp` 数字原样复制给转子侧，会发生什么？

转子的位置误差已经被减速比放大：

```math
p_{des}-p=N(q_{des}-q).
```

电机产生的转子力矩经过减速器以后，关节力矩又放大一次：

```math
\tau_j=N\tau_m.
```

两次 `N` 叠在一起：

```math
\tau_j
=N K_{p,m}(p_{des}-p)
=N^2K_{p,m}(q_{des}-q).
```

所以要让最后的关节侧仍然表现成 `K_{p,j}`：

```math
K_{p,m}=\frac{K_{p,j}}{N^2}.
```

速度项同理：

```math
K_{d,m}=\frac{K_{d,j}}{N^2}.
```

这个平方关系很重要。对于 `N=6.33`：

```text
N² ≈ 40
```

如果把关节侧增益不做换算就直接填到转子侧接口，等效关节反馈会放大约 40 倍，而不是“差一点”。

因此上层关节命令：

```text
q_des
dq_des
tau_ff
kp
kd
```

靠近电机 SDK 时要分别变成：

```text
p_des      = N * q_des
omega_des  = N * dq_des
tau_motor  = tau_ff / N
kp_motor   = kp / N²
kd_motor   = kd / N²
```

## 单圈编码器为什么不能单独告诉你真实转子角

到这里，命令方向已经能从关节侧换到转子侧。反馈方向还多一个问题：编码器读到的位置并不一定是连续的转子位置 `p`。

本培训采用安装在转子侧的单圈绝对值编码器。假设真实转子已经转到：

```text
380°
```

单圈编码器只保存这一圈里的位置，重新读回时可能得到：

```text
20°
```

数学上：

```math
p_{raw}=p\bmod 2\pi.
```

所以看到同一个 `p_raw=20°` 时，真实转子位置可能是：

```text
20°
380°
740°
...
```

统一写成：

```math
p=p_{raw}+2k\pi,
```

其中整数 `k` 是累计整圈数。

把这些候选位置再除以减速比：

```math
q_k=\frac{p_{raw}+2k\pi}{N}.
```

相邻两个候选关节位置之间相差：

```math
\Delta q=\frac{2\pi}{N}.
```

若 `N=19/3`：

```text
Δq ≈ 56.8°
```

所以丢掉一圈转子计数，在关节侧并不是“小误差”，而会得到另一个相差几十度的候选姿态。

刚上电时，单圈读数本身无法推出唯一的 `k`。程序还需要额外信息，例如机器人被放在约定的启动姿态，并且这个姿态对应的整圈数已经通过标定确定。运行起来以后，才可以利用相邻采样继续维护这个整圈数。

## 运行中怎样发现跨过了单圈边界

假设相邻两个采样之间，真实转子不可能一次转过半圈。

如果原始读数从：

```text
350° → 10°
```

普通减法得到：

```text
10° - 350° = -340°
```

但真实转子很可能只是向正方向跨过了 360° 边界，实际变化约为：

```text
+20°
```

相反：

```text
10° → 350°
```

通常表示向负方向跨界，实际变化约为：

```text
-20°
```

因此可以比较：

```text
curr_raw - prev_raw
```

若：

```text
curr_raw - prev_raw > π
```

说明读数从低端跳到了高端，对连续角度来说跨过的是负方向边界：

```text
turns -= 1
```

若：

```text
curr_raw - prev_raw < -π
```

说明读数从高端跳到了低端：

```text
turns += 1
```

随后恢复连续转子位置：

```math
p=p_{raw}+2\pi\cdot turns.
```

## 编码器零点还不是机器人关节零点

现在假设已经得到连续转子位置 `p`。

直接除以减速比：

```math
\frac{p}{N}
```

得到的是输出端相对于**电机编码器零点**的机械角。但机器人希望把哪个机械姿态定义成 `q=0`，是另一件事。

假设某个标定姿态下测得连续转子位置为 `p_0`，并希望这个姿态就是：

```text
q = 0
```

定义：

```math
q=\frac{p}{N}+offset.
```

代入标定点：

```math
0=\frac{p_0}{N}+offset,
```

得到：

```math
offset=-\frac{p_0}{N}.
```

于是反馈方向变成：

```text
单圈编码器 p_raw
→ 用 turns 恢复连续转子位置 p
→ p / N
→ 加软件零位 offset
→ 机器人关节角 q
```

反过来，上层给关节目标 `q_des` 时：

```math
p_{cmd}=N(q_{des}-offset).
```

所以位置的两个方向可以写成互逆函数：

```python
def motor_to_joint_position(p, ratio, offset):
    return p / ratio + offset


def joint_to_motor_position(q, ratio, offset):
    return ratio * (q - offset)
```

现在真实电机和上层控制之间已经有了明确边界：

```text
上层控制
q / dq / tau / kp / kd
        ↓
减速比 + 软件零位
        ↓
转子侧命令
p / omega / tau_motor / kp_motor / kd_motor
        ↓
SDK

SDK 单圈位置反馈
        ↓
恢复 turns 和连续 p
        ↓
除以减速比 + 软件零位
        ↓
上层关节状态 q
```
