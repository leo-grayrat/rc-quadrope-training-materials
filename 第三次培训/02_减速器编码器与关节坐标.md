# 减速器、编码器与关节坐标

上一篇已经把 MuJoCo 里的 `qpos / qvel / ctrl` 接到了关节控制：程序读取关节角和角速度，用 PD 等控制律算出力矩，再把力矩交给 actuator。

真实四足机器人多出一层很重要的机械结构。腿通过减速器连接电机转子，编码器也首先测量转子侧的位置，所以“程序里的关节角”和“电机内部看到的角度”并不天然是同一个量。

这一篇只抓一条主线：

```text
机器人关节侧
q, dq, tau_joint
        ↕ 减速器
电机转子侧
p, omega, tau_motor
        ↕ 编码器 / 驱动器
SDK 读写的状态和命令
```

视频第二段里看起来很多的新名词，基本都落在这三层之间的变换上。

文中为了直观看机械位置，有时继续使用 10°、30°、350° 这样的角度；真正写控制程序时，内部统一使用 rad。需要和人输入或显示的角度互换时，可以用：

```python
import math

angle_rad = math.radians(angle_deg)
angle_deg = math.degrees(angle_rad)
```

这样公式、MuJoCo 状态和后面的电机命令都保持同一套单位。

## 1. 一个真实关节里为什么会同时出现两套角度、速度和力矩

视频用宇树关节电机举例。先看结构图里的两个部位：

- **转子侧**：电机内部高速旋转的一侧；
- **输出端**：减速器外侧的输出法兰，机器人腿部机构连接在这里。

![](images/video2_01m05s_motor_structure.png)
*视频中的关节电机结构图：内侧转子与外侧输出端*

电机转子适合较高转速，输出端则需要较低速度和更大的关节力矩。减速器把两端连接起来：转子转很多圈，输出端只转一圈，同时把力矩放大。

视频以约 $`6.33:1`$ 的减速比讲解，也就是转子约转 6.33 圈，输出端转一圈。原 `motor.pdf` 还写了 $`19:3`$。下面统一记减速比为 $`N`$，具体数值只会影响换算结果，不改变推导。

定义：

- $`p`$：转子角度；
- $`\omega`$：转子角速度；
- $`\tau_m`$：转子侧力矩；
- $`q`$：输出端，也就是机器人关节角；
- $`\dot q`$：关节角速度；
- $`\tau_j`$：关节侧力矩；
- $`N`$：转子转速与输出端转速之比。

本篇先假定电机正方向和关节正方向已经统一。实际整机若某个关节安装方向相反，再在电机接口处统一处理符号，不把方向修正散到上层控制公式里。

### 从位置和速度开始

既然转子转 $`N`$ 圈、输出端转一圈，就有：

```math
p=Nq,
```

```math
\omega=N\dot q.
```

因此上层希望关节到达 $`q_{des}`$ 时，真正给电机转子侧的位置目标应该是：

```math
p_{des}=Nq_{des}.
```

目标速度同理：

```math
\omega_{des}=N\dot q_{des}.
```

![](images/video2_05m30s_mapping.png)
*视频中的输出端与转子侧位置、速度、力矩及增益换算表*

例如 $`N=6.33`$，输出端希望转到 30°，转子目标角约为：

```math
30^\circ\times 6.33=189.9^\circ.
```

所以 SDK 里看到的位置数字如果属于转子侧，就不能直接拿去当机器人关节角。

### 力矩关系来自功率守恒

忽略减速器损耗时，两侧机械功率近似相同：

```math
\tau_m\omega=\tau_j\dot q.
```

又有：

```math
\omega=N\dot q,
```

所以：

```math
\tau_j=N\tau_m.
```

减速器把转子侧力矩放大到输出端。反过来，如果上层希望关节获得力矩 $`\tau_j`$，转子侧只需要：

```math
\tau_m=\frac{\tau_j}{N}.
```

到这里三条核心换算可以放在一起看：

| 关节侧目标 | 转子侧命令 |
|---|---|
| $`q_{des}`$ | $`p_{des}=Nq_{des}`$ |
| $`\dot q_{des}`$ | $`\omega_{des}=N\dot q_{des}`$ |
| $`\tau_j`$ | $`\tau_m=\tau_j/N`$ |

位置、速度和力矩之间的方向差异都来自同一个机械关系。

## 2. 减速器怎样继续影响 PD 增益和代码接口

视频表格还直接给出：

```math
K_{p,m}=\frac{K_{p,j}}{N^2},\qquad
K_{d,m}=\frac{K_{d,j}}{N^2}.
```

这里容易显得突然，因为上一行还是“位置乘 $`N`$、力矩除 $`N`$”，下一行增益就出现了平方。把上一篇的 PD 和刚才的减速器关系连起来，平方会自然出现。

先只看位置项。上层希望在关节侧得到：

```math
\tau_j=K_{p,j}(q_{des}-q).
```

电机驱动器内部按转子侧角度误差计算：

```math
\tau_m=K_{p,m}(p_{des}-p).
```

转子角误差比关节角误差大 $`N`$ 倍：

```math
p_{des}-p=N(q_{des}-q).
```

转子侧力矩经过减速器后又放大 $`N`$ 倍：

```math
\tau_j=N\tau_m.
```

两步合起来：

```math
\tau_j
=N K_{p,m}(p_{des}-p)
=N^2K_{p,m}(q_{des}-q).
```

要让这一结果等于原本想要的

```math
K_{p,j}(q_{des}-q),
```

就有：

```math
K_{p,m}=\frac{K_{p,j}}{N^2}.
```

速度项完全相同：速度误差先因为坐标换算乘一次 $`N`$，力矩再通过减速器乘一次 $`N`$，所以：

```math
K_{d,m}=\frac{K_{d,j}}{N^2}.
```

真实电机控制因此最好长期保留“关节侧”和“电机侧”两套语义。上层控制器使用：

```text
q_des
dq_des
tau_ff
kp
kd
```

靠近 SDK 的接口再换成：

```text
p_des
omega_des
tau_motor
kp_motor
kd_motor
```

代码里可以把这五个换算集中到一个函数中。函数的输入就是上面的关节侧量和减速比，输出可以继续用已经学过的字典保存：

```python
def joint_command_to_motor(q_des, dq_des, tau_ff, kp, kd, ratio):
    # 根据上面的五条换算关系构造并返回字典
    ...
```

这样上层站立状态、目标轨迹和关节控制仍然只关心机器人的关节；更换减速比时，变化集中在电机接口这一层。

### 练习 1：自己写一次关节侧到电机侧的换算

假设上层给出：

```text
q_des = 0.4 rad
dq_des = 0.0 rad/s
tau_ff = 6 N·m
kp = 30 N·m/rad
kd = 2 N·m·s/rad
N = 6
```

自己算出转子侧的：

```text
p_des
omega_des
tau_motor
kp_motor
kd_motor
```

然后补完 `joint_command_to_motor()`，让它返回这五个量。练习结束后再检查：如果把 $`N`$ 改成 3，哪些量按一次比例变化，哪些量按平方关系变化？重点是看懂整条换算，而不是只代一次数字。

## 3. 编码器为什么让“角度”问题突然变复杂

命令方向经过减速器已经能从关节侧换到转子侧，反馈方向还要处理编码器。

视频讨论的是安装在转子侧的单圈绝对值编码器。它首先给出转子相对于编码器自身零点的角度。

![](images/video2_12m00s_encoder.png)
*视频中的单圈绝对值编码器示意*

如果暂时不考虑零位问题，转子角和关节角满足：

```math
q=\frac{p}{N}.
```

所以 SDK 读回转子位置以后，程序至少要先除以减速比，才能回到输出端的关节角。

真正麻烦的是“单圈”。单圈绝对值编码器掉电再上电以后，可以恢复当前这一圈里的位置，却不知道此前累计转过多少整圈。

例如真实转子角是 380°，重新上电后可能只读到：

```text
20°
```

可以写成：

```math
p_{raw}=p\bmod 2\pi.
```

只知道 $`p_{raw}`$ 时，真实转子位置可能是：

```math
p=p_{raw}+2k\pi,
```

其中整数 $`k`$ 表示累计的整圈数。

把它再除以减速比：

```math
q_k=\frac{p_{raw}+2k\pi}{N}.
```

于是同一个圈内读数会对应多个候选关节位置。相邻候选位置之间相差：

```math
\Delta q=\frac{2\pi}{N}.
```

![](images/video2_17m30s_zero_count.png)
*视频中用多个“零点”表示不同转子整圈对应的输出端候选位置*

视频为了直观，用“输出端一圈大约有 6.33 个零点”来描述这种现象；原 PDF 进一步给出 $`19:3`$，即转子 19 圈对应输出端 3 圈。若采用 $`19:3`$，相邻候选位置在输出端相差：

```math
\frac{3}{19}\times360^\circ\approx56.8^\circ.
```

这里最重要的是：编码器保留了圈内位置，整圈数 $`k`$ 丢失；减速器又把这个丢失的整圈数映射成不同的关节位置。

### 练习 2：判断“读数一样”到底意味着什么

设 $`N=6`$，某次重启后编码器读到：

```text
p_raw = 20°
```

只考虑 $`k=0,1,2`$ 三种可能，分别算出对应的三个关节候选位置。

然后回答两个问题：

1. 单看 `20°` 这个圈内读数，为什么不能判断机器人关节当前到底在哪一个候选位置？
2. 如果机器人每次都以接近同一趴卧姿态开机，这个机械先验信息能帮助程序做什么？

## 4. 从编码器坐标建立机器人自己的关节坐标

即使已经选对了转子整圈数，编码器的零点也通常不会和机器人希望定义的关节零点重合。

四足控制程序更希望使用一套有机械意义的坐标。例如可以规定腿处于某个统一机械姿态时关节角为 0。这样上层看到的是统一的关节坐标，每台电机自己的编码器零点都在接口处换算掉。

![](images/video2_20m30s_zero_positions.png)
*视频中的开机位置、候选零点和软件零位示意*

完整反馈过程可以写成：

```text
编码器单圈读数 p_raw
        ↓
确定当前对应的整圈数 k
        ↓
得到连续转子位置 p
        ↓ 除以减速比 N
得到输出端机械角
        ↓ 软件零位偏移
得到上层关节角 q
```

前半段解决“丢了多少整圈”，最后一步解决“机器人把哪个机械姿态叫作 0”。

### `offset` 就是坐标原点的平移

假设经过减速比换算后，某个机械位置在旧坐标里是 30°。如果希望把旧坐标的 50° 位置定义成新的 0°，那么同一个机械位置在新坐标里应该读成：

```math
30^\circ-50^\circ=-20^\circ.
```

机械位置没有变化，变化的是软件坐标。

视频口述采用“反馈减一个偏移，下发时再加回去”的写法；原 PDF 对 `offset` 使用了相反的符号约定。程序里只要固定一种定义，并让反馈和命令互为逆操作即可。

例如定义：

```math
q=\frac{p}{N}+offset.
```

那么从关节目标反算转子目标：

```math
p_{cmd}=N(q_{des}-offset).
```

代码可以集中写成：

```python
def motor_to_joint_position(p, ratio, offset):
    return p / ratio + offset


def joint_to_motor_position(q, ratio, offset):
    return ratio * (q - offset)
```

如果希望某个已知转子位置 $`p_0`$ 对应关节零位 $`q=0`$，代入上式：

```math
offset=-\frac{p_0}{N}.
```

这就是“把某个实际机械姿态标定成软件零点”在公式里的形式。

## 5. 单圈边界、10°→350° 和重启后的圈数修正

视频最后讨论的 10° 到 350°，是单圈角度表示中最容易误判的一种情况。

![](images/video2_31m40s_wrap_example.png)
*视频中的 10° 到 350° 零点跳变示例*

如果只做普通减法：

```text
350° - 10° = 340°
```

看起来像突然转了很远。放到圆周上看，10° 和 350° 实际只隔 20°，只是跨过了 0°/360° 边界。

程序里可以先计算经过回绕的角度差。内部统一使用 rad 时：

```python
def wrap_to_pi(angle):
    return (angle + math.pi) % (2 * math.pi) - math.pi


def wrapped_delta(curr, prev):
    return wrap_to_pi(curr - prev)
```

这一层回答“同一圈的角度表示跨过边界后，实际连续变化了多少”。

重启后的问题还多一步：单圈编码器不记得之前累计了多少整圈。视频给出的判断思路是看边界两侧的跳变方向。用角度表示时，例如把 0°～30° 看作低端、330°～360° 看作高端：

```text
上一次在低端，本次跑到高端
    → 实际更可能是向负方向跨过 0°
    → 当前累计圈数减 1

上一次在高端，本次跑到低端
    → 实际更可能是向正方向跨过 360°
    → 当前累计圈数加 1
```

例如：

```text
10° → 350°
```

若机械姿态只发生了小变化，就应理解成大约 `-20°` 的连续变化，而不是 `+340°`。为了让连续转子位置和上一时刻接上，此时整圈编号应向负方向修正一圈。

反过来：

```text
350° → 10°
```

对应大约 `+20°` 的连续变化，整圈编号向正方向增加一圈。

实际代码可以把边界阈值写成 rad，例如：

```python
low = math.radians(30)
high = math.radians(330)
```

随后根据 `prev_raw`、`curr_raw` 落在哪个区间来更新累计圈数 `k`。阈值只是为了把“明显跨过单圈边界”与普通圈内运动区分开，具体数值可以结合实际噪声和一次控制周期内允许的最大转角调整。

这样反馈侧的数据顺序就很清楚：

```text
SDK / encoder 原始读数 p_raw
        ↓
根据连续变化更新累计圈数 k
        ↓
p = p_raw + 2kπ
        ↓
除以减速比 + offset
        ↓
上层关节角 q
```

任务中机器狗通常以相近姿态开机时，还可以用已知的启动姿态帮助选择初始候选圈数。单圈边界判断负责随后运动中的连续性，启动姿态则帮助解决“刚上电时应该落在哪个候选位置”。

命令方向再反过来：

```text
关节侧目标
q_des / dq_des / Kp / Kd / tau_ff
        ↓
减速比 + offset
        ↓
电机侧命令
p_des / omega_des / Kp_motor / Kd_motor / tau_motor
        ↓
SDK
```

### 练习 3：从异常读数推回连续转子位置

某个关节上一时刻的圈内读数是 12°，下一时刻变成 352°，机械上只允许在这么短的时间内转动很小的角度。

2. 判断累计圈数 `k` 应该增加还是减少，并说明原因；
3. 写出从 `p_raw` 和 `k` 得到连续转子位置 `p`，再得到上层关节角 `q` 的公式。
