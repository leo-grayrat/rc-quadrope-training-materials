# 第三次任务实现

第三次任务同时包含仿真和实体电机两部分。仿真侧直接使用关节状态和力矩：

```text
q / dq
  ↓
PD / 阻尼 / 前馈
  ↓
tau
  ↓
data.ctrl
```

实体电机侧还要经过转子、减速器和编码器：

```text
关节侧 q / dq / tau
  ↕ 减速比、零位、编码器
转子侧 p / omega / tau_motor
  ↕
电机 SDK
```

原始要求以 [第三次培训任务.pdf](./第三次培训任务.pdf) 为准。

## 1. 仿真：阻尼与连续站立

控制 12 个驱动关节时，每个关节至少需要关联：

```text
joint name
actuator name
qpos address
qvel address
actuator id
```

可以继续使用字典保存这些信息：

```python
joints = {
    "FL_hip_joint": {
        "actuator_name": "FL_hip_motor",
        "qpos_adr": ...,
        "qvel_adr": ...,
        "actuator_id": ...,
    },
    # 其余关节
}
```

字典中的地址和 id 都应从模型实际查询得到。

### Viewer 中的按键

MuJoCo 的 passive viewer 可以接收一个 `key_callback`：

```python
DAMPING = 0
STANDING = 1

keyboard = {
    "requested_state": DAMPING,
}


def key_callback(keycode):
    key = chr(keycode).upper()

    if key == "D":
        keyboard["requested_state"] = DAMPING
    elif key == "S":
        keyboard["requested_state"] = STANDING
```

启动 Viewer 时把回调传进去：

```python
with mujoco.viewer.launch_passive(
    model,
    data,
    key_callback=key_callback,
) as viewer:
    ...
```

回调只记录想切换到哪个状态；真正的状态切换和控制计算留在仿真主循环里。

### 阻尼状态

阻尼模式使用：

$$
\tau=-K_d\dot q.
$$

每个关节读取当前 `dq`，得到反向力矩，限幅后写给对应 actuator：

```text
qvel
  ↓
dq
  ↓
-Kd * dq
  ↓
limit
  ↓
data.ctrl
```

如果某个关节正在向正方向转，阻尼力矩应该为负；方向相反时，力矩也应反转。

### 站立状态需要一条连续目标轨迹

站立使用：

$$
\tau
=
K_p(q_{des}-q)
+K_d(\dot q_{des}-\dot q).
$$

设切换到站立状态时的实际关节角为 $q_0$，最终站立姿态为 $q_{stand}$，整个过程用时 $T$。经过时间：

$$
t_{elapsed}=t-t_0.
$$

归一化进度：

$$
s=\mathrm{clip}\left(\frac{t_{elapsed}}{T},0,1\right).
$$

目标位置：

$$
q_{des}(s)=(1-s)q_0+s q_{stand}.
$$

在线性运动阶段：

$$
\dot q_{des}=\frac{q_{stand}-q_0}{T}.
$$

到达最终姿态后：

$$
\dot q_{des}=0.
$$

切换到站立状态的瞬间保存：

```python
q_start = {
    name: data.qpos[info["qpos_adr"]]
    for name, info in joints.items()
}
stand_start_time = data.time
```

最终站立角可以用同样的字典保存：

```python
q_stand = {
    "FL_hip_joint": ...,
    # 其余关节
}
```

### 练习：把连续目标生成独立出来

练习目录：

```text
starter/04_trajectory/
```

补全：

```python
def linear_target(q_start, q_target, elapsed, duration):
    ...
```

返回当前时刻的：

```text
q_des
dq_des
```

当 `elapsed >= duration` 时，位置应保持在最终目标，目标速度应为 0。完成后运行：

```bash
cd starter/04_trajectory
bash test.sh
```

评测会检查起点、中点、终点、超过终点以及反方向运动。通过时最后会显示：

```text
5 / 5 tests passed
```

这个函数通过以后，再把它对 12 个关节逐个调用，并接到第一篇已经通过评测的 `pd_torque()` 上。主循环中的关系就是：

```text
按键请求状态
      ↓
状态切换时保存 q_start / t0
      ↓
每轮生成 q_des / dq_des
      ↓
pd_torque(...)
      ↓
data.ctrl[actuator_id]
      ↓
mj_step()
```

阻尼状态则直接用同一个 `pd_torque()`，令 `kp=0`、`dq_des=0`、`tau_ff=0`。

## 2. 实机：把关节目标接到电机 SDK

实体部分先用宇树官方 SDK 例程跑通单电机。读示例时需要定位下面这些量对应的字段：

```text
当前转子位置 p
当前转子速度 omega
目标位置 p_des
目标速度 omega_des
Kp / Kd
tau_ff
```

程序内部仍以关节侧量组织目标：

```python
joint_state = {
    "q": ...,
    "dq": ...,
}

joint_command = {
    "q_des": ...,
    "dq_des": ...,
    "kp": ...,
    "kd": ...,
    "tau_ff": ...,
}
```

发送到 SDK 前，使用第二篇的换算：

```text
Joint Command
      ↓
减速比 + offset
      ↓
Motor Command
      ↓
SDK
```

反馈方向反过来：

```text
SDK feedback
      ↓
连续转子位置 / 速度
      ↓
减速比 + offset
      ↓
Joint State
```

### 缓慢回到 0 与键盘目标

实体任务要求先让电机缓慢回到 0，再根据输入角度缓慢转到新目标。目标生成仍然使用同一个 `linear_target()`：

```text
读取当前关节角 q_now
        ↓
q_start = q_now
        ↓
linear_target(...)
        ↓
q_des / dq_des
        ↓
joint_command_to_motor(...)
        ↓
SDK
```

人输入角度时可以继续使用 degree，进入程序后立即转成 rad：

```python
import math

angle_deg = float(input("target angle (deg): "))
q_target = math.radians(angle_deg)
```

`input()` 放在两次运动之间；一次运动真正开始以后，控制循环应连续运行到目标结束。

在连接真实电机前，可以先确认两个纯软件评测都已经通过：

```bash
cd starter/02_motor_mapping
bash test.sh

cd ../04_trajectory
bash test.sh
```

这样实际接 SDK 时，减速比换算和目标轨迹已经分别有独立的机械验收。

## 3. 软件零位和单圈跳变

假设程序采用：

$$
q=\frac{p}{N}+offset,
$$

那么反向下发目标时：

$$
p_{cmd}=N(q_{des}-offset).
$$

可以把位置换算写成两个互逆函数：

```python
def motor_to_joint_position(p, ratio, offset):
    ...


def joint_to_motor_position(q, ratio, offset):
    ...
```

任选若干 `p`，先转成 `q` 再转回 `p_back`，结果应回到原值。

单圈编码器运行时保留上一时刻的 `prev_raw` 和累计圈数 `turns`：

```text
curr_raw
   ↓
update_encoder(prev_raw, curr_raw, turns)
   ↓
连续转子位置 p
   ↓
减速比 + offset
   ↓
关节角 q
```

刚上电时没有历史，需要结合已知启动姿态选择合理的初始 `turns`；运行起来以后，再由连续采样维持圈数。

在接入真实反馈前，先运行：

```bash
cd starter/03_encoder
bash test.sh
```

评测通过以后，再把同一函数接到 SDK 的实际编码器读数上。

## 4. 最终程序中的数据流

仿真侧：

```text
按键 / 当前状态
        ↓
目标生成
q_des(t), dq_des(t)
        ↓
PD / 阻尼
        ↓
tau
        ↓
MuJoCo ctrl / mj_step
```

实机侧：

```text
目标生成
q_des(t), dq_des(t)
        ↓
关节侧命令
        ↓
减速比 / offset
        ↓
电机侧命令
        ↓
Unitree SDK
        ↓
单圈编码器反馈
        ↓
连续转子位置
        ↓
关节状态 q / dq
```

四个本地评测分别覆盖控制律、减速比换算、编码器连续化和目标轨迹。真正上仿真或实机时，剩下需要现场观察的主要是模型映射是否正确、机器人姿态是否符合预期，以及真实机械系统有没有异常抖动、碰限位或其它硬件问题。
