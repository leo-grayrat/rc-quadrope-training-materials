# 关节电机与关节控制

第二次培训已经留下了一条没有填满的数据流：

```text
当前关节状态 q / dq
        ↓
      ？
        ↓
关节力矩 tau
        ↓
data.ctrl
        ↓
mj_step()
```

现在只解决中间这个问号：已知关节现在在哪里、转得多快，程序怎样算出这一时刻应该施加的力矩。

## 力矩为什么会改变下一时刻的关节状态

在最简单的单自由度转动模型里：

```math
I\ddot q = \sum \tau .
```

`I` 是这一转动自由度对应的转动惯量，`\ddot q` 是角加速度。对同一个关节来说，净力矩方向改变，角加速度方向也跟着改变。

在 MuJoCo 程序里，这条物理关系不需要自己积分。程序负责算当前要给 actuator 的 `tau`：

```python
data.ctrl[actuator_id] = tau
```

随后：

```python
mujoco.mj_step(model, data)
```

由 MuJoCo 根据模型的惯量、重力、接触等共同计算下一步的 `qpos` 和 `qvel`。

所以控制器真正能决定的是：

```text
看到当前 q / dq
→ 选择 tau 的大小和方向
```

## 只看位置：关节偏到哪边，就往相反方向拉

假设目标角是：

```text
q_des = 0.5 rad
```

现在关节只有：

```text
q = 0.2 rad
```

还差：

```text
q_des - q = +0.3 rad
```

要让关节继续往正方向加速，控制力矩应该为正。

反过来，如果：

```text
q = 0.8 rad
```

那么：

```text
q_des - q = -0.3 rad
```

控制力矩应该改成负方向。

最直接的写法就是让力矩与位置误差成正比：

```math
\tau_p = K_p(q_{des}-q),\qquad K_p>0.
```

例如：

```python
position_error = q_des - q
tau_p = kp * position_error
```

于是：

```text
q < q_des
→ position_error > 0
→ tau_p > 0

q > q_des
→ position_error < 0
→ tau_p < 0
```

这个项始终把关节往目标位置拉。若角度使用 rad、力矩使用 N·m，则 `Kp` 的单位可以写成 N·m/rad。

### 只看位置为什么还不够

现在考虑另一个瞬间：

```text
q = q_des
dq > 0
```

关节正好经过目标角，但仍然向正方向转。

此时位置误差为 0：

```math
q_{des}-q=0,
```

所以位置项给出的力矩也是：

```math
\tau_p=0.
```

但关节的速度并没有凭空消失。它会继续越过目标；越过去以后，位置项才重新产生反方向力矩，再把它拉回来。只有位置反馈时，目标附近很容易出现反复越过和拉回。

这个失败说明控制器还漏看了一个已经存在的状态：`dq`。

## 把当前速度也放进控制器

如果希望关节最终停在目标位置，那么目标速度就是：

```text
dq_des = 0
```

当实际速度 `dq > 0` 时，需要负力矩抑制它；当 `dq < 0` 时，需要正力矩抑制它。

因此速度项写成：

```math
\tau_d = K_d(\dot q_{des}-\dot q).
```

在 `\dot q_{des}=0` 时：

```math
\tau_d=-K_d\dot q.
```

代码里就是：

```python
velocity_error = dq_des - dq
tau_d = kd * velocity_error
```

这个力矩和当前运动方向相反，所以起到阻尼作用。

把刚才的位置项和速度项放在一起：

```math
\tau
=
K_p(q_{des}-q)
+
K_d(\dot q_{des}-\dot q).
```

这就是这里使用的 PD 控制：

```text
位置误差
→ 决定往目标哪边拉

速度误差
→ 决定怎样抑制当前运动

两项相加
→ 当前关节力矩
```

视频中的电机接口把位置、速度写成 `p`、`ω`。本篇在 MuJoCo 关节侧继续使用 `q`、`dq`；下一篇会专门解释真实电机转子侧的 `p / ω` 为什么不能直接和关节侧 `q / dq` 混在一起。

## 已经知道一部分力矩时：前馈

有时控制器在看位置、速度误差之前，就已经有一个希望直接施加的力矩，例如上层算法计算出的补偿量。把这部分记为：

```math
\tau_{ff}.
```

它不由当前误差产生，而是直接和两个反馈项相加：

```math
\tau
=
\tau_{ff}
+
K_p(q_{des}-q)
+
K_d(\dot q_{des}-\dot q).
```

现在完整公式里的每一项都有来源：

```text
tau_ff
  已知的直接力矩

Kp(q_des-q)
  根据位置误差把关节拉向目标

Kd(dq_des-dq)
  根据速度误差抑制或跟随运动
```

不同的“控制模式”只是把其中一些量设为 0 或给不同目标：

| 目的 | 参数选择 | 得到的关系 |
|---|---|---|
| 直接力矩 | `Kp=0, Kd=0` | `tau=tau_ff` |
| 阻尼 | `Kp=0, dq_des=0, tau_ff=0` | `tau=-Kd*dq` |
| 位置保持 | `dq_des=0, tau_ff=0` | PD |
| 速度跟随 | 主要使用 `dq_des, Kd` | 根据速度误差给力矩 |

## 力矩不能无限大

如果误差很大：

```math
K_p(q_{des}-q)+K_d(\dot q_{des}-\dot q)
```

也可能得到很大的数，但真实执行器有输出范围，仿真任务同样会给力矩限制。

因此在写入 `data.ctrl` 前再做一次限幅：

```python
tau = (
    tau_ff
    + kp * (q_des - q)
    + kd * (dq_des - dq)
)

tau = max(-tau_limit, min(tau, tau_limit))
data.ctrl[actuator_id] = tau
```

超过正上限时返回 `tau_limit`，超过负上限时返回 `-tau_limit`。

## 把控制函数接回 MuJoCo

对一个已经有 `motor` actuator 的 hinge joint，控制循环只需要把 2.4 的状态读取和刚才的力矩计算接起来：

```python
q = data.qpos[qpos_adr]
dq = data.qvel[qvel_adr]

tau = pd_torque(
    q,
    dq,
    q_des,
    dq_des,
    kp,
    kd,
    tau_ff,
    tau_limit,
)

data.ctrl[actuator_id] = tau
mujoco.mj_step(model, data)
```

于是完整链条变成：

```text
data.qpos / data.qvel
        ↓
      q / dq
        ↓
位置误差 + 速度误差 + 前馈
        ↓
       tau
        ↓
data.ctrl[actuator_id]
        ↓
     mj_step
        ↓
新的 q / dq
```

## 一个关节为什么同时会出现几套编号

完整四足模型里，一个驱动关节至少会涉及：

```text
joint id
qpos 起始下标
qvel 起始下标
actuator id
```

按 joint 名得到 joint id：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    joint_name,
)
```

再得到它在状态数组中的位置：

```python
qpos_adr = model.jnt_qposadr[joint_id]
qvel_adr = model.jnt_dofadr[joint_id]
```

而 actuator 自己有另一套 id。假设 MJCF 中写：

```xml
<motor name="joint1_motor" joint="joint1"/>
```

则：

```python
actuator_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_ACTUATOR,
    "joint1_motor",
)
```

这个 id 才用于：

```python
data.ctrl[actuator_id] = tau
```

所以控制一个 joint 时真正走的是：

```text
joint_name
   ↓
joint_id
   ├─→ qpos_adr → q
   └─→ qvel_adr → dq

actuator_name
   ↓
actuator_id
   ↓
data.ctrl[actuator_id] = tau
```
