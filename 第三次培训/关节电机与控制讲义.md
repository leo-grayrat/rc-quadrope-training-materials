# 第三次培训：关节电机与控制

这份讲义配合[第三次培训任务](./任务.md)使用。先读[第二次培训的状态、执行器与控制](../第二次培训/MuJoCo/04_状态执行器与控制.md)，确认自己已经能从关节名找到 `qpos`、`qvel` 地址，为驱动关节配置 motor actuator，并理解 `data.ctrl → mj_step()`。本次在此基础上学习关节控制律、转子与输出端换算、软件零位。视频讲了原理，没有提供完整的状态机或实机程序；这些仍是任务的一部分。

本讲义对照[两段视频](./README.md)和原始 [motor.pdf](./motor.pdf)整理。视频中的便于口述的近似与需要确认的实机条件已显式标出。

## 1. 先分清三个位置

1. **仿真关节**：MuJoCo 模型中的 hinge joint。`data.qpos`、`data.qvel` 描述模型关节的角度与角速度。
2. **电机转子**：电机内部高速旋转的一侧。宇树官方 actuator SDK 的示例明确提醒，示例命令字段按转子侧解释。
3. **减速器输出端**：与机器人腿部机构相连的一侧。控制目标通常按此处的关节角、角速度和力矩讨论。

视频采用 GO-M8010-6 举例。宇树该型号产品页给出的减速比为 **1:6.33**：近似地说，转子转 6.33 圈，输出端转一圈。这是该型号的例子，不是所有电机的固定值。进入实机前，需要确认手里的**准确型号、固件和 SDK 版本**，再采用相应参数换算。

## 2. 把电机近似成受控力矩源

从上层控制程序看，可先用“给定力矩，电机尽量输出相应力矩”的模型理解关节电机。它不是无限精确的力矩源：摩擦、电流限制和转速都会改变实际输出。第一版仿真先实现理想控制律和限幅；需要比较 sim2real 差异时再逐项考虑延迟、摩擦、噪声等因素。

视频和 PDF 使用的控制式为

$$
\tau=\tau_{\mathrm{ff}}+K_p(p_{\mathrm{des}}-p)+K_d(\omega_{\mathrm{des}}-\omega).
$$

| 符号 | 意义 | 在此式中的作用 |
|---|---|---|
| $p$、$\omega$ | 当前角度、角速度 | 来自反馈 |
| $p_{\mathrm{des}}$、$\omega_{\mathrm{des}}$ | 目标角度、角速度 | 决定希望到哪里、以多快速度运动 |
| $K_p$ | 位置增益 | 位置误差越大，修正力矩越大 |
| $K_d$ | 速度增益 | 速度误差产生修正力矩；目标速度为零时提供阻尼 |
| $\tau_{\mathrm{ff}}$ | 前馈力矩 | 直接加到反馈控制项上 |

式子里没有积分项，所以这是**带前馈的 PD 控制式**。`MIT` 是原资料对这组混合控制命令的称呼，不应把它理解成“电机里完整控制过程只有这一条式子”。

把不同项设成零，就能读出几种模式：

| 目的 | 控制式保留的主要部分 | 初学时应观察什么 |
|---|---|---|
| 阻尼 | $\tau=-K_d\omega$ | 转得越快，反向力矩越大；这是仿真任务的一个状态 |
| 朝目标位置运动 | $K_p(p_{\mathrm{des}}-p)$，可加入阻尼项 | 刚度与振荡如何变化 |
| 速度控制 | $K_d(\omega_{\mathrm{des}}-\omega)$ | 速度是否接近目标 |
| 力矩前馈 | $\tau_{\mathrm{ff}}$ | 反馈项为零时仍可有指令力矩 |

“所有命令量置零”只说明这个理想公式给出零力矩**指令**，不等于已经证明某台实机必定自由转动或主动抵消摩擦；还要看具体控制模式及电机实现。

### 在 MuJoCo 中接上这条控制链

上次培训已做过 `joint → motor actuator → data.ctrl → mj_step()`。对简单的单自由度 hinge、`gear="1"` 且没有其它缩放时，可以把 `<motor>` 的控制输入按关节驱动力矩理解。MuJoCo 官方将 `<motor>` 定义为直接驱动执行器；`<position>` 则自带位置伺服。本任务选 `<motor>`，是为了在程序里明确计算这条控制式，而不是把目标角度直接塞进执行器。

对每个驱动关节，思考下列数据链即可，具体状态机与代码留给任务实现：

```text
关节名 → joint id → qpos / qvel 地址 → 读取关节状态
      → 根据当前模式算目标力矩 → 限幅 → 对应 actuator 的 data.ctrl
      → mj_step() → 下一轮读取
```

要检查 `joint id`、`qpos` 地址、`qvel` 地址和 `actuator id` 各自是什么，不能认为它们是同一个下标。`ctrlrange` 的数值也必须与所用模型和执行器的实际含义一致。

仿真任务有“阻尼”和“站立”两个状态。进入站立时，任务要求从**切换时的当前姿态**连续过渡到目标姿态；不能仅把目标角度瞬间改成站立角。过渡时长、目标站姿、允许的初始姿态和验收标准尚未写清，见[任务书的待确认项](./任务.md#待培训负责人确认)。

## 3. 输出端目标怎样变成转子侧命令

忽略传动损失，设减速比为 $N$、转子位置为 $p$、输出端角度为 $q$，暂时不考虑零位偏移，则

$$p=Nq,\qquad \omega=N\dot q,\qquad \tau_{\mathrm{out}}=N\tau_{\mathrm{rotor}}.$$

因此输出端要到 $q_{\mathrm{des}}$，转子侧目标位置为 $Nq_{\mathrm{des}}$；目标速度也乘 $N$；希望在输出端获得的前馈力矩要除以 $N$ 后发给转子。要让两侧的 PD 式产生一致的理想输出，还需令

$$K_{p,\mathrm{rotor}}=\frac{K_{p,\mathrm{out}}}{N^2},\qquad
K_{d,\mathrm{rotor}}=\frac{K_{d,\mathrm{out}}}{N^2}.$$

为什么是平方？把位置误差 $p_{\mathrm{des}}-p=N(q_{\mathrm{des}}-q)$ 放进转子侧控制式后，输出力矩还会再被减速器乘一次 $N$。两个 $N$ 相乘，因此增益需除以 $N^2$。速度项同理。宇树官方 SDK 的 README 也给出了这一换算，同时特别指出 A1/B1 示例还有型号相关的额外系数；不能把理想换算表原样推广到其他型号。

## 4. 单圈读数与软件零位

视频以转子侧单圈绝对值编码器为前提：重启后能知道当前圈内位置，却不能仅由这一读数恢复重启前累计转过的整圈数。转子跨过一个整圈边界，圈内读数回绕；输出端在这期间移动约 $1/N$ 圈。这是位置坐标问题，不是位置增益或力矩的“零位”。

原 PDF 进一步称精确传动关系为 **19:3**，即转子转 19 圈对应输出端转 3 圈。按此关系，相邻转子圈内零位对应的输出端位置相隔 $3/19$ 圈，约 56.8°。视频把它口述成“一圈约六个零点”只是帮助想象间距；**不能写成一圈恰好有 6.33 个离散零点**。宇树公开产品页标注的是四舍五入的 6.33，未在该页给出 19:3；需要以实际型号资料核对这一更精确的机械参数。

软件可以为每个关节保存一个 `offset`，让上层统一使用有机械意义的关节坐标。沿用原 PDF 的符号约定：

$$
q_{\mathrm{joint}}=\frac{p_{\mathrm{feedback}}}{N}+\mathrm{offset},\qquad
p_{\mathrm{command}}=N(q_{\mathrm{target}}-\mathrm{offset}).
$$

第一式负责把反馈解释成关节角；第二式是逆变换，负责把关节目标送回电机坐标。**同一个偏移量必须在收和发两个方向采用相反运算。**若把软件零位沿旧坐标的正方向挪 30°，在这个定义下 `offset` 应减少 30°；角度单位要先统一为弧度或角度。对物理零位的测量方法、标记位置和实际 SDK 反馈范围，原任务还没有完整定义。

### 重启后的歧义

保存 `offset` 还不够。若重启后的转子圈内读数对应了相邻的候选位置，原偏移会把输出端角度解释错约 $3/19$ 圈。视频用 10° 到 350° 的**转子侧圈内读数**说明跨界回绕；换到输出端，这两个圈内读数约为 1.6° 和 55.3°，但仅凭这两个数字无法确定真实机械姿态。

因此，实机程序不能把“读数大幅变化”直接等同于“必然只跳了一个零点”。需要有机械参考姿态、历史记录或其它可验证条件；无法确定时应停止自动位置运动并请负责实机的老队员核对。视频提到的区间阈值只是讲者举例，没有给出可直接照搬的判定程序。

## 5. 回到本次任务

先按[任务.md](./任务.md)完成仿真状态机。建议依次确认：模型中的 12 个驱动关节及执行器映射、阻尼状态、从当前状态连续起立、切回阻尼的行为。记录输入、状态变化和观察结果，验收时才能说明为什么程序符合要求。

实机部分按原任务分为 SDK 例程、缓慢返回零位与输入角度、零位偏移 30°、零点跳变处理四步。视频只讲了原理，没有展示完整接线和控制程序；完成实机前，需由负责人员确认电机型号、供电和接线、角度单位与参考零位、力矩和速度限制、停止条件，并核实软件里实际读取与下发的是哪一侧的量。

原 PDF 引用队内 `black` 仿真配置的力矩限值 **33.5 N·m**；宇树 GO-M8010-6 产品页给出的该型号最大力矩是 **23.7 N·m**。两者不能视为同一电机的可互换设置。仿真数值与实机参数应分别按对应模型、器件资料和队内负责人确认。
