# 排错与验收

## 常见排错顺序

构建或运行失败时，先判断问题出在哪一层，再去改代码。

### 找不到文件或程序

先确认当前目录和文件：

```bash
pwd
ls
tree
```

如果运行的是：

```bash
./build/robot_demo
```

就先确认 `build/robot_demo` 是否真的存在。

### 找不到头文件

典型错误：

```text
fatal error: robot/motor.hpp: No such file or directory
```

检查：

- `#include` 中的路径是否正确；
- 手动编译时是否提供了 `-Iinclude`；
- CMake 中是否给正确的 target 配置了 `target_include_directories()`；
- 当前构建的是不是预期的工程目录。

### 编译错误

编译器通常会给出源文件、行号和错误类型。先处理最前面的错误位置，再重新编译。后面连续出现的错误有时只是前面一处语法错误引起的。

例如：

```cpp
left_motor_.enable(
```

括号没有闭合，当前源文件无法正常编译。

### undefined reference

这类错误出现在链接阶段。

常见原因：

- 函数已经声明，但没有定义；
- 头文件声明和 `.cpp` 中的定义签名不一致；
- 提供函数定义的 `.cpp` 没有参与构建；
- 可执行 target 没有链接需要的 library target。

例如，声明了：

```cpp
void DMMotor::enable();
```

并不代表链接器一定能找到它的实现。

### 修改代码后结果没有变化

检查：

- 文件是否已经保存；
- 当前修改的是不是正在构建的那份源码；
- 是否重新执行了 `cmake --build build`；
- 运行的是否是刚刚生成的 `./build/robot_demo`。

如果机器上存在多个同名工程或多个 `build/`，这类问题很常见。

## 验收时需要掌握的内容

完成这一部分后，至少应能结合自己的代码说明：

- 类和对象的区别；
- 成员变量和成员函数分别表示什么；
- `public`、`private` 如何控制访问；
- 为什么 `Motor` 的状态要通过成员函数修改；
- 构造函数何时执行；
- 成员初始化列表怎样初始化成员；
- `const` 成员函数限制了什么；
- `explicit` 在这里解决什么问题；
- 纯虚函数和抽象类的作用；
- `override` 为什么有用；
- `Motor&` 怎样引用不同的具体电机；
- `Robot` 为什么保存 `Motor&`；
- 引用成员对对象生命周期有什么要求；
- 头文件和 `.cpp` 文件分别放什么；
- 编译和链接分别发生什么；
- `-Iinclude` 的作用；
- CMake 中 executable target 和 library target 的关系；
- `add_library`、`add_executable`、`target_link_libraries` 的基本用法。

现场修改可能包括：

- 给 `Motor` 增加 `disable()`，并在两种具体电机中实现；
- 把目标位置从 `1.50` 改成 `-0.80`；
- 新增一种 `Motor` 实现，再交给 `Robot` 使用；
- 从构建配置中漏掉一个源文件，判断出现的是编译错误还是链接错误。
