# 机器狗任务实现

这一部分把前面的知识用于第二次培训任务。

最终需要完成：

```text
URDF → MJCF
机器人 + 平地
motor actuator
合理的初始趴卧姿态
ctrl = 0
运行后稳定
```

## 1. 转换后先检查模型

先用 Viewer 打开转换得到的 MJCF：

```bash
python3 -m mujoco.viewer --mjcf=path/to/robot.xml
```

先检查：

- mesh 是否完整；
- 四条腿位置是否正常；
- joint 轴方向是否明显错误；
- base 是否能自由运动；
- 有没有严重穿模。

如果 mesh 找不到，检查 XML 中的 `meshdir`、`mesh file` 和实际文件路径。

## 2. 用程序检查模型结构

前面已经学过：

```python
model.nq
model.nv
model.nu
model.njnt
```

先把这些值打印出来，并根据自己的机器人解释它们为什么是这个数。

例如自由基座 + 12 个 hinge joint：

```text
nq = 19
nv = 18
```

如果结果与模型结构对不上，先检查 MJCF。

## 3. 检查 joint

使用前面介绍的：

```python
mujoco.mj_name2id(...)
model.jnt_qposadr[...]
```

确认实际使用的 12 个驱动 joint 名称以及它们在 `qpos` 中的位置。

这一阶段至少应该能列出：

```text
joint name
joint id
qpos address
```

## 4. 加入 motor actuator

给每个驱动 joint 配置一个 motor actuator。

完成以后再次检查：

```python
print(model.nu)
print(data.ctrl)
```

任务使用 12 个独立单输入 actuator 时，预期 `nu = 12`。

还要核对每个 actuator 的 `joint="..."` 是否指向正确关节。

## 5. 加入平地

建立场景文件，用 `include` 加载机器人，再加入 plane geom。

打开 Viewer 后应同时看到机器人和地面。

## 6. 设置初始姿态

需要设置：

- base 的初始高度；
- 各腿关节的初始角。

具体角度由机器人模型决定。可以根据 joint 名找到对应 `qpos` 下标，再修改 `data.qpos`。

修改完成后调用：

```python
mujoco.mj_forward(model, data)
```

先在 Viewer 中确认初始姿态没有严重穿地或悬空。

## 7. 零力矩运行

进入仿真前：

```python
data.ctrl[:] = 0.0
```

循环中保持零输入并调用 `mj_step()`。

任务要求零力矩，因此不要加入姿态保持控制器。

## 8. 判断是否稳定

观察：

- base 是否继续下沉、漂移；
- 腿是否持续滑动；
- 是否剧烈抖动或弹飞；
- `data.qvel` 是否逐渐变小。

最终检查：

```text
模型可加载          ✓
mesh 完整           ✓
平地存在            ✓
12 个驱动 joint     ✓
motor actuator      ✓
ctrl = 0            ✓
初始趴卧姿态合理    ✓
运行后稳定          ✓
```

到这里，人工任务中的基础 MuJoCo 仿真部分完成。
