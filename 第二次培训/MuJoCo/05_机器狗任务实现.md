# 机器狗任务实现

前面已经分别把 falling box、single joint、motor actuator 跑通。完整机器狗仍然使用同样的 body、joint、geom、actuator 和状态，只是数量更多。

这次任务最终要达到：

```text
URDF
  ↓
转换并整理成 MJCF
  ↓
机器人放入平坦场景
  ↓
驱动关节配置 motor actuator
  ↓
设置合理的初始趴卧姿态
  ↓
data.ctrl[:] = 0.0
  ↓
运行后稳定
```

任务要求的是零力矩下合理趴卧，不需要让机器狗走起来。

## 1. 先学会读一小段 URDF

URDF 也是 XML，因此标签、属性、嵌套关系的读法和前面的 MJCF 相同。不同的是它使用另一套机器人描述标签。

先看一个只有两个刚体、一个关节的例子：

```xml
<robot name="mini_robot">
    <link name="base"/>
    <link name="thigh"/>

    <joint name="hip_joint" type="revolute">
        <parent link="base"/>
        <child link="thigh"/>
        <axis xyz="0 1 0"/>
        <limit lower="-1.0" upper="1.0" effort="20" velocity="5"/>
    </joint>
</robot>
```

先只看两个 `link`：

```xml
<link name="base"/>
<link name="thigh"/>
```

`link` 表示机器人中的刚体部件。这里有一个 `base` 和一个 `thigh`。

再看 joint：

```xml
<joint name="hip_joint" type="revolute">
```

`name="hip_joint"` 是关节名；`type="revolute"` 表示这是一个有角度范围的旋转关节。

它下面的：

```xml
<parent link="base"/>
<child link="thigh"/>
```

给出了父子关系：

```text
base
  ↓ hip_joint
thigh
```

所以这个 joint 连接 `base` 和 `thigh`。

旋转轴：

```xml
<axis xyz="0 1 0"/>
```

表示绕 Y 轴旋转。

关节限制：

```xml
<limit lower="-1.0" upper="1.0" effort="20" velocity="5"/>
```

其中：

- `lower`、`upper`：允许的角度下限和上限，旋转关节中使用弧度；
- `effort`：最大允许驱动力矩或力；
- `velocity`：最大允许关节速度。

完整四足机器人的 URDF 只是出现更多 link 和 joint。读文件时仍然按照同样的关系逐个追踪。

### link 中的外形和物理参数

实际 URDF 的 `link` 往往不是空标签。例如：

```xml
<link name="thigh">
    <visual>
        <geometry>
            <mesh filename="meshes/thigh.stl"/>
        </geometry>
    </visual>
</link>
```

这里 `visual` 描述显示外形，`mesh filename` 指向模型文件。

还可能同时出现：

- `collision`：碰撞时使用的几何形状；
- `inertial`：质量、质心和惯量。

因此拿到完整机器狗 URDF 后，可以先完成一张简单记录：

```text
joint name        parent          child           axis
-----------------------------------------------------------
...               ...             ...             ...
```

至少把腿部驱动 joint 的名称和父子关系整理清楚。后面转换成 MJCF 后还要再次核对这些关系。

培训任务指定使用：

```text
https://urdf.enkeebot.com/zh/
```

完成 URDF → MJCF。

转换前已经知道每个驱动 joint 连着谁、绕哪个轴转，转换结果就不再是一份完全陌生的 XML。

## 2. 转换完成后先让模型单独打开

直接运行：

```bash
python3 -m mujoco.viewer --mjcf=models/robot.xml
```

这一步只检查模型：

- 四条腿是否都存在；
- 左右、前后腿位置是否正确；
- mesh 是否缺失；
- 某个 link 是否明显错位；
- joint 的方向和范围是否和 URDF 对得上；
- 机身是否有 freejoint；
- 有没有严重自相交。

如果这里就有问题，先回到 MJCF 或资源路径处理。Python 控制程序还没有参与。

### mesh 资源是怎样接进模型的

真实机器人的外形通常来自 STL、OBJ 等 mesh 文件。MJCF 会先在 `asset` 中声明这种资源，例如：

```xml
<asset>
    <mesh name="body_mesh" file="body.stl"/>
</asset>
```

这里：

- `file` 指向真实 mesh 文件；
- `name` 给这份资源一个 MJCF 内部名称。

某个 geom 再引用它：

```xml
<geom type="mesh" mesh="body_mesh"/>
```

如果很多 mesh 都放在同一个目录，还可能看到：

```xml
<compiler meshdir="../meshes"/>
```

`meshdir` 给 mesh 文件设置公共目录。这样 `file="body.stl"` 会从这个目录下寻找。

### mesh 找不到时

报错说 mesh 找不到时，依次确认：

1. `compiler` 中有没有 `meshdir`；
2. `asset` 中对应 `mesh` 的 `file` 写了什么；
3. XML 文件和 mesh 目录的真实相对位置。

再看真实文件：

```bash
pwd
find . -type f | sort
```

相对路径会随着 XML 所在位置变化。只移动 XML、不保持原来的 mesh 目录结构，很容易导致资源找不到。

## 3. 用已经学过的程序检查模型结构

加载模型：

```python
model = mujoco.MjModel.from_xml_path("models/robot.xml")
data = mujoco.MjData(model)
```

先看：

```python
print("nq =", model.nq)
print("nv =", model.nv)
print("njnt =", model.njnt)
```

如果模型是：

```text
1 个 freejoint
+
12 个 hinge
```

常见结果是：

```text
nq = 19
nv = 18
```

因为：

```text
freejoint:
qpos 7
qvel 6

12 个 hinge:
qpos 12
qvel 12
```

这个结果应该能从模型结构直接解释。

## 4. 把实际 joint 名称列出来

上一节已经学过 `model.njnt` 和 `mj_id2name()`。

现在把所有 joint 打出来：

```python
for joint_id in range(model.njnt):
    name = mujoco.mj_id2name(
        model,
        mujoco.mjtObj.mjOBJ_JOINT,
        joint_id,
    )
    print(joint_id, name)
```

先只看名字。需要从结果中确认：

- 哪一个是基座自由关节；
- 腿部驱动 joint 分别叫什么；
- 这些名字能否和刚才读 URDF 时整理出的 joint 对应起来。

确认名字以后，再增加状态地址：

```python
print(
    joint_id,
    name,
    model.jnt_qposadr[joint_id],
    model.jnt_dofadr[joint_id],
)
```

这一步把：

```text
关节名字
↓
joint id
↓
qpos / qvel 地址
```

对应到实际机器狗模型。

## 5. 给驱动 joint 配 motor actuator

上一节已经在 single joint 上做过一次。机器狗只是把同样的配置重复到所有驱动关节。

假设某个实际 joint 名为：

```text
FL_hip_joint
```

就在 `actuator` 中加入：

```xml
<motor name="FL_hip_motor" joint="FL_hip_joint" gear="1"/>
```

其它驱动 joint 也分别增加一个 motor。

完成后重新加载模型：

```python
print(model.nu)
print(data.ctrl)
```

如果有 12 个独立单输入 motor，通常会看到：

```text
model.nu = 12
```

以及 12 个初始为 0 的控制输入。

检查：

- 有没有漏掉某个驱动 joint；
- actuator 的 `joint="..."` 是否拼对；
- 有没有两个 actuator 错接到同一个 joint。

## 6. 把机器人放进平地场景

机器人本体可以放在：

```text
models/robot.xml
```

场景另写：

```text
scenes/flat_scene.xml
```

先建立一个只包含机器人本体的场景骨架：

```xml
<mujoco model="flat_scene">
    <include file="../models/robot.xml"/>

    <worldbody>
    </worldbody>
</mujoco>
```

`include` 会把另一个 MJCF 文件中的内容并入当前模型。

然后在 `worldbody` 中加入已经学过的 plane：

```xml
<geom name="floor" type="plane" size="5 5 0.1"/>
```

这里相对 falling box 只增加了一个新概念：机器人本体来自另一个文件。

直接检查：

```bash
python3 -m mujoco.viewer --mjcf=scenes/flat_scene.xml
```

应同时看到机器人和地面。

## 7. 给 freejoint 一个明确名字

后面需要修改基座高度。先确认基座 freejoint 有名字。

如果转换结果中是：

```xml
<freejoint/>
```

可以改成：

```xml
<freejoint name="base_freejoint"/>
```

这样它可以和普通 joint 一样通过已经学过的 `mj_name2id()` 查找。

先找到：

```python
base_joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "base_freejoint",
)
```

再得到它在 `qpos` 中的起始位置：

```python
base_qpos_adr = model.jnt_qposadr[base_joint_id]
```

freejoint 的 7 个位置状态依次是：

```text
x y z qw qx qy qz
```

所以：

```python
data.qpos[base_qpos_adr + 2]
```

就是基座 z 坐标。

例如：

```python
data.qpos[base_qpos_adr + 2] = 0.25
```

表示把基座初始高度设为 0.25 m。

具体高度由机器人尺寸决定：

- 太高时，机器人会先明显下落；
- 太低时，机身或腿可能一开始就穿进地面。

## 8. 先只调一个腿部 joint

先选一个实际 joint，例如：

```text
FL_hip_joint
```

按上一节的方法查它：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "FL_hip_joint",
)
```

得到 qpos 地址：

```python
qpos_adr = model.jnt_qposadr[joint_id]
```

先只改这一项：

```python
data.qpos[qpos_adr] = 0.3
```

然后：

```python
mujoco.mj_forward(model, data)
```

在 Viewer 中观察这个 joint 到底向哪个方向转。

通过单个关节逐步确认：

- hip、thigh、calf 各自对应哪个 joint；
- 正角度和负角度分别朝哪个方向；
- 左右腿是否需要相反符号；
- joint range 允许哪些角度。

这一步把一个数值对应回真实机械结构。

## 9. 再把所有初始角整理起来

每个 joint 的方向都确认以后，可以用 Python 字典保存初始角：

```python
initial_joint_positions = {
    "FL_hip_joint": ...,
    "FL_thigh_joint": ...,
    "FL_calf_joint": ...,
}
```

具体名字和数值来自实际模型。

遍历字典：

```python
for name, position in initial_joint_positions.items():
    ...
```

循环中的每个 joint 都做三步：

1. 用名字得到 joint id；
2. 用 joint id 得到 qpos 地址；
3. 把对应角度写进 `data.qpos`。

先得到 id：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    name,
)
```

再得到地址：

```python
qpos_adr = model.jnt_qposadr[joint_id]
```

最后写入：

```python
data.qpos[qpos_adr] = position
```

把这三步放进 `for`，就能依次设置所有关节。

所有初始状态设置完以后，再统一调用：

```python
mujoco.mj_forward(model, data)
```

## 10. 先检查初始姿态，再开始仿真

此时先不连续执行 `mj_step()`。

在 Viewer 中检查：

- 机身高度是否合理；
- 四条腿是否朝正确方向折叠；
- 有没有明显穿地；
- 左右姿态是否符合模型结构。

如果这时已经不对，问题来自模型或初始 `qpos`，还没有进入动态控制阶段。

## 11. 零力矩运行

任务要求关节输出力矩为 0：

```python
data.ctrl[:] = 0.0
```

然后进入已经熟悉的循环：

```python
mujoco.mj_step(model, data)
viewer.sync()
```

零力矩时机器人仍然受到重力、地面接触力、关节阻尼、摩擦等物理作用。

合理现象可能是：机器人先发生一点沉降和调整，随后稳定。

## 12. 怎样判断任务已经完成

Viewer 中至少观察：

- base 是否持续下沉或漂移；
- 腿是否一直滑动；
- 是否持续抖动或弹飞；
- 有没有明显穿透地面；
- 某个 joint 是否一直撞到 range。

还可以看：

```python
print(data.qvel)
```

经过短暂运动后，稳定模型的速度应该逐渐变小。

最后应该能够明确指出：

- 使用的是哪份机器人 MJCF；
- URDF 中的主要 joint 和 MJCF 中的 joint 怎样对应；
- freejoint 在哪里；
- 驱动 joint 分别叫什么；
- actuator 在哪里定义；
- flat scene 在哪里；
- base 高度在哪里设置；
- 腿部初始角在哪里设置；
- `data.ctrl[:] = 0.0` 在哪里执行；
- 依据什么判断机器人已经稳定。

做到这些，基础 MuJoCo 任务就完成了。
