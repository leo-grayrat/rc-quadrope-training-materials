# 机器狗任务实现

前面已经分别看过自由方块和单关节模型。完整机器狗没有换一套机制，它只是同时包含更多 body、joint、geom 和 actuator。

这次任务最终要达到：

```text
URDF
  ↓
转换并整理成 MJCF
  ↓
机器人放入平坦场景
  ↓
12 个驱动关节配置 motor actuator
  ↓
设置合理的初始趴卧姿态
  ↓
data.ctrl[:] = 0.0
  ↓
运行后稳定
```

任务要求的是零力矩下合理趴卧，不需要让机器狗走起来。

## 1. 先整理文件

建议先把文件放成：

```text
quadruped_sim/
├── models/
│   ├── robot.xml
│   └── meshes/
├── scenes/
│   └── flat_scene.xml
└── simulate.py
```

这样模型、mesh、场景和程序的位置比较清楚，后面遇到相对路径问题也更容易判断。

## 2. 转换之前先看 URDF

培训任务给的是 URDF。不要把转换网站当成“输入文件、下载结果”就结束，至少先在 URDF 中找到：

- 机身和四条腿分别有哪些 `link`；
- 腿部驱动关节的 `joint name`；
- 每个 joint 的父子 link；
- `axis` 和 `limit`；
- mesh 文件从哪里引用；
- inertial 信息是否存在。

后面 MJCF 中出现的 body、joint、mesh 和惯量信息，都来自这些机器人结构。

培训任务指定使用：

```text
https://urdf.enkeebot.com/zh/
```

完成 URDF → MJCF。当前 MuJoCo 本身已经能够解析符合要求的 URDF，但这次培训仍要求显式完成转换，因为后面需要直接阅读和修改 MJCF、加入执行器并组织场景。

## 3. 转换完成后先让模型单独打开

先不写控制代码，直接检查转换后的模型：

```bash
python3 -m mujoco.viewer --mjcf=models/robot.xml
```

此时重点看模型本身：

- 四条腿是否都存在；
- 左右、前后腿位置是否正确；
- mesh 有没有缺失；
- 某一节腿有没有明显转错方向；
- 关节范围是否看起来异常；
- 机身是否具有自由基座；
- 模型是否已经严重自相交。

如果这里就有问题，优先修改 MJCF 或资源路径。Python 控制程序此时还没有参与，不应通过改控制代码解决模型加载问题。

### mesh 找不到时

例如报错指向某个 STL/OBJ 文件，先看：

```xml
<compiler meshdir="..."/>
```

以及：

```xml
<mesh file="..."/>
```

再从 XML 所在位置检查真实文件：

```bash
pwd
find . -type f | sort
```

移动 XML 文件以后，相对 mesh 路径也可能随之失效。

## 4. 用程序把模型结构打印出来

现在才进入 Python。

先加载模型并打印：

```python
print("nq =", model.nq)
print("nv =", model.nv)
print("nu =", model.nu)
print("njnt =", model.njnt)
```

如果模型是一个自由基座加 12 个单自由度腿部关节，常见结果是：

```text
nq = 19
nv = 18
```

这个结果应该能用前面的知识解释：

```text
free joint:
qpos 7
qvel 6

12 个 hinge:
qpos 12
qvel 12
```

接着把 joint 名称和状态位置列出来：

```python
for joint_id in range(model.njnt):
    name = mujoco.mj_id2name(
        model,
        mujoco.mjtObj.mjOBJ_JOINT,
        joint_id,
    )

    print(
        joint_id,
        name,
        model.jnt_qposadr[joint_id],
        model.jnt_dofadr[joint_id],
    )
```

这里不要求输出必须和某个示例一样。你需要从自己的输出中确认：

- 哪个是自由基座；
- 12 个驱动关节分别叫什么；
- 它们在 `qpos` 中从哪里开始。

如果连这几个问题还答不上来，就先不要继续写初始姿态。

## 5. 给驱动关节加入 motor actuator

URDF 转成 MJCF 后可能已经有 joint，但不一定有任务要求的 actuator。

对一个驱动关节：

```xml
<joint
    name="FL_hip_joint"
    type="hinge"
    axis="1 0 0"
/>
```

可以配置：

```xml
<actuator>
    <motor
        name="FL_hip_motor"
        joint="FL_hip_joint"
        gear="1"
    />
</actuator>
```

四足机器人有 12 个独立驱动关节时，通常需要分别配置 12 个 motor actuator。

完成以后重新加载模型：

```python
print(model.nu)
print(data.ctrl)
```

本任务这种 12 个独立单输入 motor 的模型，预期 `model.nu` 为 12，初始 `data.ctrl` 中有 12 个 0。

同时回到 XML 检查每个 actuator 的 `joint="..."`：

- 有没有漏掉某条腿；
- 有没有写错 joint 名；
- 有没有两个 actuator 都接到了同一个 joint。

## 6. 建立平坦场景

机器人本体放在 `models/robot.xml`，平地场景可以单独写：

```xml
<mujoco model="flat_scene">
    <include file="../models/robot.xml"/>

    <worldbody>
        <light pos="0 0 3"/>

        <geom
            name="floor"
            type="plane"
            size="5 5 0.1"
            rgba="0.8 0.8 0.8 1"
        />
    </worldbody>
</mujoco>
```

保存为：

```text
scenes/flat_scene.xml
```

然后直接检查：

```bash
python3 -m mujoco.viewer --mjcf=scenes/flat_scene.xml
```

这里的 `../models/robot.xml` 是相对 `flat_scene.xml` 的文件位置。场景能打开以后，应同时看到机器人和地面。

如果机器人文件和场景文件都定义了全局 `compiler`、`option` 等设置，要留意最终合并后的配置，不要在两个文件里无意中重复定义相互冲突的全局参数。

## 7. 初始趴卧姿态到底要设置什么

机器人开始仿真时的姿态由两部分组成：

```text
机身的空间位姿
+
12 个腿部关节角
```

### 机身高度

free joint 在 `qpos` 中使用：

```text
x y z qw qx qy qz
```

如果检查结果确认 free joint 的 `qpos` 起始地址为 0，那么：

```python
data.qpos[2]
```

就是机身初始高度。

更一般地，可以先找到 free joint：

```python
for joint_id in range(model.njnt):
    if model.jnt_type[joint_id] == mujoco.mjtJoint.mjJNT_FREE:
        base_qpos_adr = model.jnt_qposadr[joint_id]
        break
```

那么：

```python
data.qpos[base_qpos_adr + 2] = ...
```

设置的是这个 free joint 的 z 坐标。

高度过高，机器人会先明显自由落体；高度过低，机身或腿可能一开始就穿进地面。

### 腿部关节角

先从刚才打印的 joint 名称中挑一个关节，只改这一处：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "FL_hip_joint",
)

qpos_adr = model.jnt_qposadr[joint_id]
data.qpos[qpos_adr] = 0.3
```

修改后：

```python
mujoco.mj_forward(model, data)
```

再在 Viewer 中看这一个关节到底向哪个方向转。

通过这种方式确认：

- hip、thigh、calf 分别对应哪个 joint；
- 正角度让腿向哪边转；
- 左右腿是否需要不同符号；
- joint range 允许哪些角度。

不要一开始同时猜 12 个数。先把一条腿调到合理折叠状态，再处理镜像腿，定位问题会简单很多。

当这些关系明确以后，再把初始角集中保存。例如 Python 字典：

```python
initial_joint_positions = {
    "FL_hip_joint": ...,
    "FL_thigh_joint": ...,
    "FL_calf_joint": ...,
}
```

字典把“关节名”和“初始角”对应起来。可以遍历它，根据名称找到 `qpos` 地址并写入角度。

具体名字和角度取决于实际机器人模型，所以这里不给固定数值。

## 8. 先看初始姿态，再开始 stepping

所有初始 `qpos` 设置完成以后调用：

```python
mujoco.mj_forward(model, data)
```

此时先同步 Viewer，检查：

- 机身是否位于地面上方合理位置；
- 四条腿是否都朝正确方向折叠；
- 有没有明显穿地；
- 左右姿态是否符合模型结构。

这一阶段还没有执行 `mj_step()`，所以看到的问题主要来自你设置的初始状态和模型本身。

## 9. 零力矩运行

任务要求关节输出力矩为 0，因此控制循环中保持：

```python
data.ctrl[:] = 0.0
```

然后像 falling box 一样推进：

```python
mujoco.mj_step(model, data)
viewer.sync()
```

零力矩不代表“锁住姿态”。机器人仍然受到重力、接触力、关节阻尼和其他物理参数影响。

如果趴卧姿态合理，机器人可能先发生一点沉降和调整，然后稳定下来；如果一开始悬空、穿模或者腿部角度不合理，它也可能继续滑动、翻倒或弹起。

## 10. 怎样判断任务已经完成

Viewer 中至少要观察：

- base 是否持续下沉或漂移；
- 腿是否一直滑动；
- 是否有周期性抖动；
- 有没有明显穿透地面；
- 某个 joint 是否持续撞到 range。

同时可以看：

```python
print(data.qvel)
```

经过短暂运动后，稳定模型的速度应该逐渐变小，而不是一直保持明显运动。

最终你应该能明确指出：

- 使用的是哪份机器人 MJCF；
- 平地场景在哪个文件；
- free joint 在哪里；
- 12 个驱动 joint 分别叫什么；
- 12 个 actuator 在哪里定义；
- 初始 base 高度在哪里设置；
- 初始腿部关节角在哪里设置；
- `data.ctrl[:] = 0.0` 在哪里执行；
- 你依据什么判断机器人已经稳定。

这时才算真正完成了人工任务中的基础 MuJoCo 仿真部分。
