# 机器狗任务实现

前面已经分别把 falling box、single joint、motor actuator 跑通。完整机器狗没有换一套机制，只是把同样的结构扩展到更多 body、joint 和 actuator。

这次任务最终要达到：

```text
URDF
  ↓
转换并整理成 MJCF
  ↓
机器人放入平坦场景
  ↓
驱动关节配置 motor actuator
  ↓
设置合理的初始趴卧姿态
  ↓
data.ctrl[:] = 0.0
  ↓
运行后稳定
```

任务要求的是零力矩下合理趴卧，不需要让机器狗走起来。

## 1. 转换之前先看 URDF

培训任务给的是 URDF。先在文件中找到这些信息：

- 机身和四条腿分别有哪些 `link`；
- 驱动关节的 `joint name`；
- 每个 joint 的父子 link；
- `axis` 和 `limit`；
- mesh 文件从哪里引用；
- inertial 信息是否存在。

后面 MJCF 中出现的 body、joint、mesh 和惯量，都能在这里找到来源。

培训任务指定使用：

```text
https://urdf.enkeebot.com/zh/
```

完成 URDF → MJCF。

转换完成以后，先不要急着写 Python 控制程序。先看生成的 MJCF 是否把原来的机器人结构正确保留下来。

## 2. 先让模型单独打开

直接运行：

```bash
python3 -m mujoco.viewer --mjcf=models/robot.xml
```

这一步只检查模型：

- 四条腿是否都存在；
- 左右、前后腿位置是否正确；
- mesh 是否缺失；
- 某个 link 是否明显错位；
- joint 的方向和范围是否合理；
- 机身是否有 freejoint；
- 有没有严重自相交。

如果这里就有问题，先回到 MJCF 或资源路径处理。Python 控制程序还没有参与。

### mesh 找不到时

先看模型中的：

```xml
<compiler meshdir="..."/>
```

以及：

```xml
<mesh file="..."/>
```

再看真实文件：

```bash
pwd
find . -type f | sort
```

相对路径会随着 XML 所在位置变化。只移动 XML、不保持原来的 mesh 目录结构，很容易导致资源找不到。

## 3. 用已经学过的程序检查模型结构

加载模型：

```python
model = mujoco.MjModel.from_xml_path("models/robot.xml")
data = mujoco.MjData(model)
```

先看：

```python
print("nq =", model.nq)
print("nv =", model.nv)
print("njnt =", model.njnt)
```

如果模型是：

```text
1 个 freejoint
+
12 个 hinge
```

常见结果是：

```text
nq = 19
nv = 18
```

因为：

```text
freejoint:
qpos 7
qvel 6

12 个 hinge:
qpos 12
qvel 12
```

这个结果现在应该能从模型结构直接解释。

## 4. 把实际 joint 名称列出来

上一节已经学过 `model.njnt` 和 `mj_id2name()`。

现在把所有 joint 打出来：

```python
for joint_id in range(model.njnt):
    name = mujoco.mj_id2name(
        model,
        mujoco.mjtObj.mjOBJ_JOINT,
        joint_id,
    )
    print(joint_id, name)
```

先只看名字，不急着继续堆更多输出。

你需要从结果中确认：

- 哪一个是基座自由关节；
- 12 个腿部驱动 joint 分别叫什么。

确认名字以后，再增加状态地址：

```python
print(
    joint_id,
    name,
    model.jnt_qposadr[joint_id],
    model.jnt_dofadr[joint_id],
)
```

这一步的目标是把：

```text
关节名字
↓
joint id
↓
qpos / qvel 地址
```

真正对应到你自己的模型。

## 5. 给驱动 joint 配 motor actuator

上一节已经在 single joint 上做过一次。

机器狗只是重复同样的配置。

假设某个实际 joint 名为：

```text
FL_hip_joint
```

就在 `actuator` 中加入：

```xml
<motor name="FL_hip_motor" joint="FL_hip_joint" gear="1"/>
```

其它驱动 joint 也分别增加一个 motor。

完成后重新加载模型：

```python
print(model.nu)
print(data.ctrl)
```

如果有 12 个独立单输入 motor，通常会看到：

```text
model.nu = 12
```

以及 12 个初始为 0 的控制输入。

检查时重点看：

- 有没有漏掉某个驱动 joint；
- actuator 的 `joint="..."` 是否拼对；
- 有没有两个 actuator 错接到同一个 joint。

## 6. 把机器人放进平地场景

机器人本体可以放在：

```text
models/robot.xml
```

场景另写：

```text
scenes/flat_scene.xml
```

先建立一个只包含机器人本体的场景骨架：

```xml
<mujoco model="flat_scene">
    <include file="../models/robot.xml"/>

    <worldbody>
    </worldbody>
</mujoco>
```

`include` 会把另一个 MJCF 文件中的内容并入当前模型。

然后在 `worldbody` 中加入已经学过的 plane：

```xml
<geom name="floor" type="plane" size="5 5 0.1"/>
```

最终只比前面的 falling box 多了一件新事：**机器人本体来自另一个文件**。

直接检查：

```bash
python3 -m mujoco.viewer --mjcf=scenes/flat_scene.xml
```

应同时看到机器人和地面。

## 7. 给 freejoint 一个明确名字

后面需要修改基座高度。为了不再引入另一套新的“按类型扫描 joint”的 API，最简单的做法是先确认基座 freejoint 有名字。

如果转换结果中是：

```xml
<freejoint/>
```

可以改成：

```xml
<freejoint name="base_freejoint"/>
```

这样它就能和普通 joint 一样通过已经学过的 `mj_name2id()` 查找。

先找到：

```python
base_joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "base_freejoint",
)
```

再得到它在 `qpos` 中的起始位置：

```python
base_qpos_adr = model.jnt_qposadr[base_joint_id]
```

freejoint 的 7 个位置状态依次是：

```text
x y z qw qx qy qz
```

所以：

```python
data.qpos[base_qpos_adr + 2]
```

就是基座 z 坐标。

例如：

```python
data.qpos[base_qpos_adr + 2] = 0.25
```

表示把基座初始高度设为 0.25 m。

具体高度要根据机器人尺寸调整：

- 太高：机器人会先明显下落；
- 太低：机身或腿可能一开始就穿进地面。

## 8. 先只调一个腿部 joint

不要一开始同时猜 12 个角度。

先选一个实际 joint，例如：

```text
FL_hip_joint
```

按上一节的方法查它：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "FL_hip_joint",
)
```

得到 qpos 地址：

```python
qpos_adr = model.jnt_qposadr[joint_id]
```

先只改这一项：

```python
data.qpos[qpos_adr] = 0.3
```

然后：

```python
mujoco.mj_forward(model, data)
```

在 Viewer 中观察这个 joint 到底向哪个方向转。

通过单个关节逐步确认：

- hip、thigh、calf 各自对应哪个 joint；
- 正角度和负角度分别朝哪个方向；
- 左右腿是否需要相反符号；
- joint range 允许哪些角度。

这一步的目的就是把“一个数字”对应回真实机械结构。

## 9. 再把所有初始角整理起来

每个 joint 的方向都确认以后，可以用 Python 字典保存初始角：

```python
initial_joint_positions = {
    "FL_hip_joint": ...,
    "FL_thigh_joint": ...,
    "FL_calf_joint": ...,
}
```

这里的具体名字和数值都来自你自己的模型。

Python 基础中已经学过字典遍历：

```python
for name, position in initial_joint_positions.items():
    ...
```

循环中的每个 joint 都做同样三步：

1. 用名字得到 joint id；
2. 用 joint id 得到 qpos 地址；
3. 把对应角度写进 `data.qpos`。

所以循环主体可以逐步写成：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    name,
)
```

然后：

```python
qpos_adr = model.jnt_qposadr[joint_id]
```

最后：

```python
data.qpos[qpos_adr] = position
```

把这三步放进 `for`，就能依次设置所有关节。

所有初始状态设置完以后，再统一调用：

```python
mujoco.mj_forward(model, data)
```

## 10. 先检查初始姿态，再开始仿真

此时先不要急着连续 `mj_step()`。

在 Viewer 中检查：

- 机身高度是否合理；
- 四条腿是否朝正确方向折叠；
- 有没有明显穿地；
- 左右姿态是否符合模型结构。

如果这时已经不对，问题来自模型或初始 `qpos`，还没有必要怀疑控制器。

## 11. 零力矩运行

任务要求关节输出力矩为 0，所以：

```python
data.ctrl[:] = 0.0
```

然后进入已经熟悉的循环：

```python
mujoco.mj_step(model, data)
viewer.sync()
```

零力矩不代表“锁住姿态”。机器人仍然受到：

- 重力；
- 地面接触力；
- 关节阻尼；
- 摩擦；
- 模型中的其它物理参数。

因此合理现象可能是：机器人先发生一点沉降和调整，随后稳定。

## 12. 怎样判断任务已经完成

Viewer 中至少观察：

- base 是否持续下沉或漂移；
- 腿是否一直滑动；
- 是否持续抖动或弹飞；
- 有没有明显穿透地面；
- 某个 joint 是否一直撞到 range。

还可以看：

```python
print(data.qvel)
```

经过短暂运动后，稳定模型的速度应该逐渐变小。

最后应该能够明确指出：

- 使用的是哪份机器人 MJCF；
- freejoint 在哪里；
- 驱动 joint 分别叫什么；
- actuator 在哪里定义；
- flat scene 在哪里；
- base 高度在哪里设置；
- 腿部初始角在哪里设置；
- `data.ctrl[:] = 0.0` 在哪里执行；
- 依据什么判断机器人已经稳定。

做到这些，才算真正完成基础 MuJoCo 任务。
