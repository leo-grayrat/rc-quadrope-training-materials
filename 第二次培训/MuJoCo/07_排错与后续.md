# 排错与后续

这一部分不再引入新的主流程，主要用于实际调试和最后验收。遇到问题时，先判断错误发生在哪一层，再去改对应内容。

## Python 找不到 mujoco

典型报错：

```text
ModuleNotFoundError: No module named 'mujoco'
```

检查：

```bash
which python3
python3 -m pip show mujoco
```

如果安装 MuJoCo 的 Python 和运行脚本的 Python 不是同一个环境，就会出现“明明装过但 import 失败”。

## XML 无法加载

MuJoCo 通常会指出出错文件和大致位置。

优先检查：

- XML 标签是否闭合；
- 属性名是否写错；
- include 路径是否正确；
- mesh 文件是否存在；
- actuator 引用的 joint 名是否真实存在；
- 被引用的 asset 名称是否拼错。

修改后重新加载。一次只改少量内容，否则很难判断是哪一项真正解决了问题。

## mesh 找不到

先看 XML：

```xml
<compiler meshdir="..."/>
<mesh file="..."/>
```

再看磁盘：

```bash
pwd
find . -name "*.stl"
find . -name "*.STL"
find . -name "*.obj"
```

相对路径和 XML 文件所在位置直接相关。只复制 `robot.xml` 而没有同时保持 mesh 目录结构，很容易导致资源失效。

## 模型能打开，但姿态明显不对

先区分“模型结构错”还是“初始 qpos 设置错”。

如果刚用命令行 Viewer 打开 `robot.xml` 就已经出现：

- 腿安装方向异常；
- mesh 错位；
- 某个 link 在远处；
- joint 转轴明显不对；

优先回到 MJCF/URDF 检查 body、joint、axis 和资源。

如果原始模型结构正常，只有运行自己的 Python 程序以后姿态才不对，再检查 `data.qpos` 的写入。

## 机器人一开始就掉下去

检查：

- 有没有 free joint；
- base 初始高度是否合理；
- 地面是否真的存在；
- 初始腿部关节角是否合理。

零力矩下，站立机器人不能自动保持站立。失去支撑后下落属于正常动力学结果。

## 机器人剧烈抖动或弹飞

先保持：

```python
data.ctrl[:] = 0.0
```

如果零控制下仍然异常，优先检查：

```text
初始穿模
↓
碰撞几何
↓
质量 / 惯量
↓
joint range
↓
接触和摩擦参数
```

不要一看到弹飞就先改控制器。模型本身已经不稳定时，控制器通常只会把问题混在一起。

## ctrl 改了但关节没有反应

先看：

```python
print(model.nu)
print(data.ctrl)
```

如果 `model.nu == 0`，模型根本没有控制输入。

如果 `nu` 正常，再检查：

- actuator 是否连接到预期 joint；
- 写的是不是正确的 ctrl 下标；
- `gear` 是否合理；
- joint 是否已经撞到 range；
- 阻尼或其他参数是否让运动很不明显。

## 调试时先看哪些量

最常用：

```python
print("time:", data.time)
print("qpos:", data.qpos)
print("qvel:", data.qvel)
print("ctrl:", data.ctrl)

print("nq:", model.nq)
print("nv:", model.nv)
print("nu:", model.nu)
```

如果数组很长，再只取关心的一段。

例如已经确认自由基座位于 `qpos[0:7]` 时：

```python
print("base position:", data.qpos[0:3])
print("joint position:", data.qpos[7:])
```

这类切片只有在已经确认模型排列以后再使用。

## 一个比较稳妥的排查顺序

完整四足模型出现问题时，可以按：

```text
Python / MuJoCo 能否正常运行
↓
MJCF 能否单独加载
↓
mesh 是否完整
↓
body / joint 结构是否正确
↓
nq / nv / nu 是否符合模型
↓
actuator 是否连接正确
↓
初始 qpos 是否合理
↓
ctrl 是否按预期写入
↓
mj_step 后状态是否正常变化
↓
最后再看控制器和线程
```

每一步只解决一类未知量。

## 完成这一阶段以后应该能做什么

至少应能够：

1. 安装并验证 MuJoCo Python 包；
2. 看懂基础 MJCF 的 body、joint、geom；
3. 加载模型并创建 `MjData`；
4. 用 `mj_step()` 推进仿真；
5. 解释 `qpos`、`qvel`、`ctrl` 与模型结构的关系；
6. 解释 free joint 为什么在 `qpos` 和 `qvel` 中占用不同维度；
7. 给 hinge joint 配置 motor actuator；
8. 根据 joint 名称定位其状态下标；
9. 建立平地场景并加载机器人；
10. 设置初始 base 位姿和腿部关节角；
11. 在零力矩下运行并判断机器人是否稳定；
12. 根据报错、Viewer 和关键状态量做基础排查；
13. 从程序入口、`mj_step`、`ctrl` 和线程开始阅读一个 MuJoCo 工程。

本阶段暂时不要求推导接触求解器、约束方程、雅可比矩阵、逆动力学等内容。
