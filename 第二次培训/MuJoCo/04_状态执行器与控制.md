# 状态、执行器与控制

上一节的 single joint 已经能转，但现在还没有任何东西主动驱动它。

## joint 和 actuator 是两回事

`joint` 只说明某个 body 允许怎样运动。

例如：

```xml
<joint
    name="joint1"
    type="hinge"
    axis="0 1 0"
/>
```

表示 `link` 可以绕 Y 轴旋转。

如果控制程序希望主动给这个关节施加作用，还需要 actuator。

当前培训任务要求力矩模式，使用 `motor` actuator：

```xml
<actuator>
    <motor
        name="joint1_motor"
        joint="joint1"
        gear="1"
    />
</actuator>
```

这里：

- `name` 是执行器名称；
- `joint` 指定它驱动哪个关节；
- `gear` 表示传动比例。

对于这里最简单的一对一 hinge joint 和 `gear="1"`，可以把 `data.ctrl` 中对应元素理解为这个 motor 的直接驱动输入。

## 先看加入 actuator 前后发生了什么

原 single joint 模型没有 actuator：

```python
print(model.nu)
print(data.ctrl)
```

结果是：

```text
0
[]
```

把上面的 `<actuator>` 段加入 MJCF 后，再加载模型：

```text
model.nu = 1
data.ctrl = [0.]
```

这说明模型现在有一个控制输入。

仓库中同时提供了加入 motor 后的参考模型：

- [starter/02_single_joint/motor_scene.xml](./starter/02_single_joint/motor_scene.xml)

### 练习：自己给 joint1 加 motor

先复制：

```text
starter/02_single_joint/scene.xml
```

然后：

1. 给 `joint1` 增加一个 `motor` actuator；
2. 重新加载模型；
3. 输出 `model.nu`；
4. 输出 `data.ctrl`。

成功后应看到一个控制输入，和 `motor_scene.xml` 的结果一致。

## ctrl 怎样让关节运动

加载带 motor 的模型：

```python
model = mujoco.MjModel.from_xml_path(
    "starter/02_single_joint/motor_scene.xml"
)
data = mujoco.MjData(model)
```

开始时：

```python
print(data.qpos)
print(data.ctrl)
```

会看到关节角和控制输入都接近 0。

现在写：

```python
data.ctrl[0] = 1.0
```

再连续推进若干步：

```python
for _ in range(100):
    mujoco.mj_step(model, data)
```

最后重新打印：

```python
print(data.qpos)
print(data.qvel)
```

关节角和角速度会发生变化。

这里已经形成一个完整对应关系：

```text
MJCF 中的 joint1
        ↓
motor actuator
        ↓
data.ctrl[0]
        ↓
MuJoCo 动力学
        ↓
data.qpos[0] / data.qvel[0] 改变
```

四足机器人只是把这条关系重复到多个关节上。

## 模型里有很多 joint 时怎么办

single joint 只有一个关节，所以直接用 `qpos[0]` 很方便。

四足机器人有很多 joint，固定写：

```python
data.qpos[7]
```

之前应该先确认这个下标到底对应哪个关节。

MJCF 中关节可以有名字：

```xml
<joint name="FL_hip_joint" .../>
```

MuJoCo 可以根据名字找到内部 joint id：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "FL_hip_joint",
)
```

然后：

```python
qpos_adr = model.jnt_qposadr[joint_id]
qvel_adr = model.jnt_dofadr[joint_id]
```

分别得到这个 joint 在 `qpos`、`qvel` 中的起始位置。

对于 single joint，可以先验证这套方法：

```python
joint_id = mujoco.mj_name2id(
    model,
    mujoco.mjtObj.mjOBJ_JOINT,
    "joint1",
)

print(joint_id)
print(model.jnt_qposadr[joint_id])
print(data.qpos[model.jnt_qposadr[joint_id]])
```

只有一个 joint 时这些值看起来有些多余，但到了 12 个关节的机器狗上，它们就能把“关节名字”和“状态数组位置”明确对应起来。

## 怎样列出模型中的关节

面对别人提供的模型，往往一开始连 joint 名都不知道。

可以遍历 `0 ... model.njnt-1`：

```python
for joint_id in range(model.njnt):
    name = mujoco.mj_id2name(
        model,
        mujoco.mjtObj.mjOBJ_JOINT,
        joint_id,
    )

    print(
        joint_id,
        name,
        model.jnt_qposadr[joint_id],
        model.jnt_dofadr[joint_id],
    )
```

输出会把每个 joint 的：

```text
id
名称
qpos 起始下标
qvel 起始下标
```

列出来。

这段程序之后会直接用于机器狗模型检查。

## qpos、qvel 和 ctrl

现在可以更完整地理解三个数组：

- `data.qpos`：模型当前的位置状态；
- `data.qvel`：模型当前的速度状态；
- `data.ctrl`：当前执行器输入。

它们的长度来自模型：

- `model.nq`
- `model.nv`
- `model.nu`

这三个长度分别由自由度和执行器配置决定，不要求彼此相等。

## 手工修改状态和 mj_forward

有时我们不是希望“施加力矩让它慢慢运动到某个姿势”，而是直接指定仿真开始时的姿态。

例如：

```python
data.qpos[0] = 0.5
```

修改状态以后调用：

```python
mujoco.mj_forward(model, data)
```

MuJoCo 会根据新的 `qpos`、`qvel` 等状态重新计算依赖量，但不会推进仿真时间。

这正适合设置机器狗的初始 base 高度和腿部关节角。

## 一个基础仿真循环

有了状态和执行器以后，控制循环可以整理为：

```text
读取当前状态
    ↓
计算控制输入
    ↓
写入 data.ctrl
    ↓
mj_step(model, data)
    ↓
viewer.sync()
```

对应代码骨架：

```python
while viewer.is_running():
    # 读取 data.qpos / data.qvel

    # 计算控制量

    # 写入 data.ctrl

    mujoco.mj_step(model, data)
    viewer.sync()
```

培训任务要求零力矩，所以最终“计算控制量”这一步非常简单：

```python
data.ctrl[:] = 0.0
```

但是零力矩并不等于机器人会保持原姿态。它仍然受到重力、接触力、关节阻尼等作用。下一篇会专门处理“怎样让一只机器狗在零力矩下合理趴在地面上”。
