# 入门与最小仿真

## MuJoCo 在机器人程序里做什么

MuJoCo 是一套刚体动力学和接触仿真引擎。对于四足机器人，它根据刚体质量、惯量、关节结构、碰撞几何和执行器等信息，计算机器人在重力、接触和控制输入作用下怎样运动。

一个最基础的仿真过程可以画成：

```text
机器人模型与场景
        ↓
      MuJoCo
        ↓
位置、速度等当前状态
        ↓
     控制程序
        ↓
力矩或其他控制输入
        ↓
      MuJoCo
        ↓
    下一时刻状态
```

当前阶段先把 MuJoCo 当成一个可以被 Python 调用的物理仿真环境。我们需要逐步弄清四件事：模型怎样描述、程序怎样加载、运行状态放在哪里、怎样推进到下一时刻。

## 安装与检查环境

Ubuntu 中先确认 Python 和 pip：

```bash
python3 --version
python3 -m pip --version
```

安装 MuJoCo：

```bash
python3 -m pip install mujoco
```

然后进入 Python：

```bash
python3
```

输入：

```python
import mujoco
print(mujoco.__version__)
```

能够输出版本号，说明当前 Python 可以找到 MuJoCo。

以后如果出现“已经安装但 import 失败”，先检查：

```bash
which python3
python3 -m pip show mujoco
```

这两条命令分别告诉你当前实际运行的 Python，以及 MuJoCo 安装在哪个 Python 环境中。

## 先看一个完整的模型

MuJoCo 原生使用 MJCF 描述模型。MJCF 是 XML 文件。现在不需要先学完整 XML，只看下面这个完整例子：

```xml
<mujoco model="falling_box">
    <option timestep="0.002" gravity="0 0 -9.81"/>

    <worldbody>
        <light pos="0 0 3"/>

        <geom
            name="floor"
            type="plane"
            size="5 5 0.1"
        />

        <body name="box" pos="0 0 1">
            <freejoint/>
            <geom
                type="box"
                size="0.1 0.1 0.1"
                mass="1"
            />
        </body>
    </worldbody>
</mujoco>
```

这份模型只描述几件事：

- 世界里有一块平地；
- 有一个位于 `z=1` 的方块；
- 方块有 `freejoint`，因此可以在空间中自由移动和转动；
- 重力为 `0 0 -9.81`；
- 一个物理步对应 `0.002 s`。

所以即使还没有写 Python，也已经能预测：仿真开始后，方块会掉到地面。

仓库中已经准备好这份模型：

- [starter/01_falling_box/scene.xml](./starter/01_falling_box/scene.xml)

## 模型和运行状态

Python 中先把 XML 加载成 MuJoCo 模型：

```python
model = mujoco.MjModel.from_xml_path("scene.xml")
```

`MjModel` 保存编译后的模型结构和参数，例如刚体、关节、质量、执行器、碰撞几何和时间步长。正常仿真时，这些内容大部分不会每一步改变。

随后创建：

```python
data = mujoco.MjData(model)
```

`MjData` 保存运行过程中的状态，例如当前位置、速度、控制输入和已经经过的仿真时间。随着物理仿真不断推进，`MjData` 会持续变化。

先观察几个成员：

```python
print("nq =", model.nq)
print("nv =", model.nv)
print("nu =", model.nu)
print("time =", data.time)
```

对 falling box，刚创建 `MjData` 时会得到：

```text
nq = 7
nv = 6
nu = 0
time = 0.0
```

`nq`、`nv` 和 `nu` 的具体含义后面逐步展开。这里先记住：前三个来自模型结构，`time` 属于正在运行的状态。

## 让时间向前走

MuJoCo 用：

```python
mujoco.mj_step(model, data)
```

推进一个物理时间步。

当前 XML 中：

```xml
<option timestep="0.002" gravity="0 0 -9.81"/>
```

因此一次 `mj_step()` 对应约 `0.002 s`。连续调用 10 次以后，`data.time` 应从 `0.0` 变为约 `0.02`。

### 练习 2：推进 10 步

在刚才的程序上继续：

1. 先打印 `data.time`；
2. 调用 10 次 `mujoco.mj_step(model, data)`；
3. 再打印 `data.time`。

预期输出接近：

```text
0.0
0.020000000000000004
```

浮点数最后几位可能不同。

完成后可以和 [参考实现](./reference/02_step_time.py) 对照。

## 把仿真显示出来

MuJoCo Python 包带有 Viewer。完整示例：

- [starter/01_falling_box/simulate.py](./starter/01_falling_box/simulate.py)

运行：

```bash
cd starter/01_falling_box
python3 simulate.py
```

应该看到方块从空中下落并停到地面。

程序中的关键部分是：

```python
with mujoco.viewer.launch_passive(model, data) as viewer:
    while viewer.is_running():
        mujoco.mj_step(model, data)
        viewer.sync()
```

这里有两个不同动作：

- `mj_step()` 真正更新物理状态；
- `viewer.sync()` 把当前状态同步到窗口。

Viewer 只负责显示。即使不显示窗口，MuJoCo 仍然可以继续计算物理状态。

原示例还使用 `time.sleep()` 让显示速度大致接近真实时间。它不会改变物理计算本身。

到这里，已经有了后续所有机器人仿真都会反复出现的主骨架：

```text
加载模型
↓
创建状态
↓
循环调用 mj_step
↓
需要时同步 Viewer
```
