# 入门与最小仿真

## 模型和运行状态

MuJoCo 做动力学计算时，需要两类信息。

一类在仿真过程中基本不变，例如刚体结构、关节、质量、执行器和时间步长。MuJoCo 把这些信息编译成 `MjModel`。

另一类会随着仿真不断变化，例如当前位置、速度、控制输入和当前时间。MuJoCo 用 `MjData` 保存这些运行状态。

从 MJCF 文件创建模型：

```python
model = mujoco.MjModel.from_xml_path("scene.xml")
```

再为这个模型创建一份运行状态：

```python
data = mujoco.MjData(model)
```

后面会经常读取这些成员。

`MjModel` 中：

- `nq`：位置状态 `qpos` 的长度；
- `nv`：速度状态 `qvel` 的长度；
- `nu`：控制输入 `ctrl` 的长度；
- `opt.timestep`：一个物理仿真步对应的时间。

`MjData` 中：

- `qpos`：当前位置状态；
- `qvel`：当前速度状态；
- `ctrl`：当前控制输入；
- `time`：已经仿真的时间。

### 练习：第一次读取模型

使用 [starter/01_falling_box/scene.xml](./starter/01_falling_box/scene.xml)，自己创建一个 `inspect.py`。

要求：

1. 加载 `scene.xml`；
2. 创建 `MjData`；
3. 依次输出 `model.nq`、`model.nv`、`model.nu` 和 `data.time`。

这个模型只有一个自由方块，没有执行器。运行结果应为：

```text
7
6
0
0.0
```

这里先不用理解为什么 free joint 对应 `7` 和 `6`，下一篇会解释。

## 推进仿真

创建 `MjData` 时，仿真时间从 `0.0` 开始。MuJoCo 用：

```python
mujoco.mj_step(model, data)
```

推进一个物理时间步。

falling box 的 XML 中设置了：

```xml
<option timestep="0.002" gravity="0 0 -9.81"/>
```

因此每调用一次 `mj_step()`，`data.time` 增加约 `0.002` 秒。

### 练习：推进 10 步

在刚才的程序上继续修改：

1. 先输出初始 `data.time`；
2. 调用 10 次 `mj_step(model, data)`；
3. 再输出 `data.time`。

预期输出接近：

```text
0.0
0.020000000000000004
```

浮点数最后几位可能不同。

完成后可以和 [参考实现](./reference/02_step_time.py) 对照。

## 打开 Viewer

物理仿真本身并不需要窗口。Viewer 只是把当前状态显示出来。

完整的 falling box 示例已经放在：

- [starter/01_falling_box/simulate.py](./starter/01_falling_box/simulate.py)

其中用到三个 Viewer 接口：

- `mujoco.viewer.launch_passive(model, data)`：创建 Viewer；
- `viewer.is_running()`：判断窗口是否仍然打开；
- `viewer.sync()`：把当前 `data` 同步到画面。

运行：

```bash
cd starter/01_falling_box
python3 simulate.py
```

应看到方块从空中下落并停在地面上。

程序中的 `time.sleep()` 只用于让显示速度大致接近真实时间；真正推进物理状态的是 `mj_step()`。
